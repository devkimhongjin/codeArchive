# 대시보드 목록 페이지와 과거 풀이 관리 — #359 / #360

## 전체 풀이

- 기존 플랫폼·문제별 제출 묶음을 유지해 **문제 목록 20개씩** 표시한다.
- 목록 위에서 이전/다음 페이지와 페이지 선택을 사용할 수 있다. 문제 범위·총 문제 수, 제출 수를 구분한다.
- 검색·플랫폼·언어·정렬을 변경하면 첫 페이지로 이동한다. 서버 목록이 줄어들면 마지막 유효 페이지로 보정한다.
- 페이지를 바꾸면 새 목록의 첫 문제를 선택하고 목록 스크롤을 위로 돌린다. 메뉴를 이동해도 현재 페이지는 유지한다.
- 커뮤니티의 내 문제로 돌아가기는 해당 문제가 있는 페이지를 연다.
- 목록 자체의 높이를 제한해 모든 문제 때문에 대시보드 전체가 늘어나지 않도록 한다.

## 과거 풀이 관리

- 주 메뉴의 **과거 풀이 관리** 또는 `?view=history`로 연다.
- 저장 안내에서 확장의 로컬 보관, 로그인한 서버 동기화, 연결된 GitHub 저장을 구분한다.
- **일괄 동기화**와 **일괄 GitHub 커밋** 버튼으로 사용할 작업 화면을 선택한다. 두 버튼은 실제 업로드/커밋을 즉시 실행하지 않는다.
- 플랫폼·제출을 선택하고 기존 실행 버튼과 GitHub 대상 미리보기를 거쳐 명시적으로 실행한다.
- 작업 화면이나 다른 메뉴로 이동해도 이미 시작한 작업과 결과가 유지된다. 브라우저 페이지를 닫으면 추가 요청은 중단되며 서버에 접수된 작업은 계속 처리한다.
- 로그인/계정/저장소 확인, 서버 중복, FAILED의 명시적 재시도, UNKNOWN 재요청 제외 규칙은 기존 계약을 따른다.

## 2026-10-06 Chrome 검증

`CODEARCHIVE_BROWSER_PAGINATION=true`로 `node test/history-browser-fixture.mjs`를 실행하고 Chrome에서 `http://127.0.0.1:5178`을 열었다.
실제 App/API 클라이언트와 합성 서버·확장 응답을 사용했다. 실제 풀이, 실제 서버 업로드, GitHub 커밋은 사용하지 않았다.

- 문제 48건/제출 49건: 페이지별 행 수 20, 20, 8과 마지막 페이지의 다음 버튼 비활성 확인.

- 동기화 55건 시작 후 커밋 화면·전체 풀이 탭 이동/복귀. 최종 55건 처리, 54건 수락, 합성 거절 1건 선택 유지 확인.
- 합성 SWEA 커밋 2건 요청 후 동기화 화면·연동 가이드 이동/복귀. 완료 진행률 2/2 및 대기/실패 0 확인.
- 새 관리 탭 URL 및 메뉴 이동, 커뮤니티에서 내 문제 복귀 확인.
- 390×844 모바일에서 두 작업 버튼, 모바일 메뉴의 새 탭, 페이지 컨트롤 및 가로 넘침 없음 확인. 임시 viewport는 해제.
