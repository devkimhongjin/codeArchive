# 커뮤니티 목록·반응·중복 공개 설정

## 구현 범위

- #316: SWEA처럼 행 형태의 공개 풀이 목록. 내 공개 제출 포함, 닉네임만 표시.
  제출 시각(KST), 언어, 실행시간, 메모리, UTF-8 코드 길이, 좋아요·댓글 수 표시.
  서버에서 제출 최신순 / 실행시간 오름차순 / 정규화한 메모리 오름차순 /
  좋아요 내림차순으로 정렬하고 20건씩 조회. 동점은 제출 시각·id 최신순.
  누락·음수 실행시간과 비교 불가능한 메모리는 마지막에 표시.
  내 풀이 공개 설정에도 제출 id·시각·성능·길이를 표시.
- #317: 풀이별 좋아요/취소와 댓글 조회·작성·수정·삭제.
  같은 문제 공유 자격과 대상 공개 상태를 모든 요청에서 검사.
  좋아요는 계정 행 잠금과 유일 키로 중복 증가 방지. 댓글은 작성자만 수정/삭제,
  최대 2,000자, 20건 페이지, React 텍스트 출력, 기존 요청 제한·CSRF·계정 검증 적용.
  비공개 철회나 계정 변경 시 접근 차단 및 화면 응답 격리.
- #395: 설정에서 전체 / 최소 실행시간 / 최소 메모리 / 최소 코드 길이 선택.
  중복 정책을 변경해 저장하면 기존 정답 풀이에도 즉시 적용.
  같은 플랫폼·문제별 하나를 선택하며 누락값 뒤로, 동점이면 최근 제출 선택.
  이후 기본 공개 신규 동기화, 수동 공개, 기존 풀이 일괄 공개에도 정책 적용.
  기본 비공개 신규 기록과 비공개로 전환한 기록의 재전송은 비공개 유지.

## 데이터 변경

- V24: 좋아요·댓글 테이블과 인덱스. 삭제 시 해당 관계 삭제.
- V25: 계정의 중복 공개 정책, 기본값 `all`. 마이그레이션 자체는 기존 공개 상태를 변경하지 않음.
- JDBC 조회/변경은 Hibernate에 설정된 스키마를 명시. 운영 `codearchive_v2`와
  이전 `public` 스키마가 섞이지 않도록 회귀 테스트 추가.
- 메모리 비교: KB=1,000 B, KiB=1,024 B, MB=1,000,000 B, MiB=1,048,576 B.
  단위 없는 값은 추정하지 않음. 표시값은 기존 공통 표시 함수 사용.

- `npm --prefix apps/dashboard test`: 197개 통과.

  건너뛴 테스트를 실행 완료로 간주하지 않음.
- 변경된 정책의 음수 측정값 처리 추가 후 커뮤니티·스키마·설정 대상 18개 테스트와 패키징 재실행. 음수/단위 미확인 경계 테스트 1개도 별도로 통과.
- `npm --prefix apps/desktop run build`: 대시보드 타입 검사·Vite 빌드,
  확장 빌드, PC 앱 renderer 및 포함 확장 생성 성공. 사용 중인 설치 폴더는 변경하지 않음.
- Chrome의 로컬 합성 데이터 화면에서 23개 제출의 20/3 페이지 이동,
  내 제출 표시, 네 정렬, 좋아요 표시/재정렬, 댓글 작성·수정·삭제,
  KST 시각, 중복 공개 옵션 선택·저장 이벤트 확인.
  이 UI 검증은 운영 API 또는 운영 계정 두 개를 사용한 검증이 아님.
- 최초 CI에서 PostgreSQL 마이그레이션은 적용됐으나 기존 개수 예상값(23)이
  새 버전(25)과 달라 테스트가 실패. 예상값을 갱신하고 V24/V25 스키마,
  기존 공개 상태 보존, PostgreSQL에서 네 정렬·좋아요·댓글 JDBC 실행 검증 추가.
  로컬에서는 PostgreSQL 환경이 없어 이 테스트의 컴파일·패키징만 확인하고,
  실제 실행 결과는 후속 CI에서 확인한다.
