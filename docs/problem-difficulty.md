# 플랫폼별 난이도 (#337)

공식 페이지의 문제 번호와 난이도가 한 항목에 연결된 경우만 저장한다. SWEA D1–D8, 프로그래머스 Lv. 0–5는 서로 다른 척도로 표시·필터링하며 교차 순위를 만들지 않는다. 정올은 solved.ac와 같은 30단계 눈금을 쓰지만 값은 정올이 자체로 매긴다. 정올 번호로 BOJ 문제나 solved.ac 티어를 조회하지 않는다.

- SWEA: 본인 제출 원본 검증 후 문제 제목의 번호와 유일한 난이도 배지를 확인한다.
- 프로그래머스: 공식 해결 목록의 문제 링크와 같은 행 Lv 셀을 확인한다. 문제 상세에 없으면 임의 추정하지 않는다.
- 정올: 제출한 문제 페이지의 유일한 `h1` 안 `.tier`에 있는 이미지 `https://s.jungol.co.kr/solved/{1–30}.svg` 하나를 Bronze V–Ruby I로 저장한다(2026-11-25 공개 페이지에서 확인). 서버는 출처가 그 정올 문제 페이지일 때만 받는다. 티어가 없는 문제는 비워 둔다.
  - 같은 이미지가 제출현황의 `제출자` 칸 등에서는 **회원의 티어**를 뜻하므로 제목 밖에서는 읽지 않는다. 제출현황의 문제 칸에는 티어가 없어 과거 수집·제출현황 동기화에는 적용하지 않는다.
  - 정올 티어는 바뀔 수 있다. 서버는 처음 저장한 값을 유지하고, 기존 풀이를 추측해 채우지 않는다.
- 백준: 백준 화면에는 난이도가 없어 solved.ac 공개 문제 API(`https://solved.ac/api/v3/problem/show?problemId={번호}`)의 `level` 1–30을 Bronze V–Ruby I로 저장한다. 응답의 `problemId`가 같은 문제일 때만 쓰고, 0(Unrated)·실패·시간 초과는 비워 둔다. 서버도 출처 URL이 그 문제의 API 주소이고 문제 주소가 `acmicpc.net/problem/{번호}`일 때만 받는다.
- 기존 제출은 누락 풀이 대조 → 기존 제출 정보 확인에서 원본을 다시 검증한 뒤 비어 있는 정보만 보강한다. 일괄 동기화로 서버에 반영한다.
- 대시보드는 확인된 난이도만 풀이 목록과 상세에 배지로 표시하고, 미확인은 표시하지 않는다. 복사·다운로드·GitHub 주석에는 `난이도`를 골랐을 때만 `Difficulty: {값}`을 쓴다(기본 해제).
- V34는 난이도 열을 20자로 늘린다. V27의 10자로는 `Platinum II`·`III`·`IV`, `Diamond III`를 저장할 수 없었다.
- V27은 nullable 열만 추가한다. 운영 풀이의 난이도를 추측하거나 일괄 변경하지 않는다.

검증: 프로그래머스 실제 Chrome 목록의 Lv. 3/Lv. 2 구조 확인; SWEA 번호/배지 연결 및 공식 URL 검증은 DOM fixture 테스트. SWEA 로그인 후 실제 원본 보강 및 설치된 확장 화면 검증은 별도 인수 조건이다.
