# Dashboard 시작 시 API 준비 대기 — Issue #146

## 범위와 판단

Dashboard 정적 화면을 열 때 API가 늦게 응답하면 기존 입장·세션 확인의 20초 제한으로 실패할 수 있다. 시작 단계에 공개 health 조회를 추가해 입장 화면과 App을 마운트하기 전에 기다린다. **모든 간헐 오류의 원인을 유휴 종료로 확정하지 않는다.** 문제 풀이 페이지에 머물렀는지도 원인으로 가정하지 않는다.

Render의 [무료 서비스 안내](https://render.com/docs/free#spinning-down-on-idle)는 15분 유휴 후 종료와 약 1분 재기동 시간을 설명한다. 실제 API 시작 로그에서 122~126초가 확인되어 전체 상한을 2분에서 **3분**으로 보완했다. 상한 뒤에는 실패 안내와 수동 재시도를 제공한다. 자동 keepalive, 상시 폴링, 유료 자원 또는 서비스 설정 변경은 추가하지 않는다.

## 동작과 경계

- `ApiReadinessGate → BetaEntryGate → App` 순서. 같은 탭의 기존 입장 승인도 상태 조회를 건너뛰지 않는다. 준비 조회는 새로운 입장 승인이나 로그인 자격이 아니며 저장하지 않는다.
- 기존 Main API의 `GET /actuator/health`만 사용한다. `credentials: omit`, `cache: no-store`, `referrerPolicy: no-referrer`, `redirect: error`; 요청 본문·인증 헤더·코드 없음. API의 기존 exact-origin CORS를 변경하지 않는다.
- HTTP 성공 및 JSON `status: "UP"`일 때만 준비 완료. DB를 포함한 health가 DOWN이거나 HTML/예상 밖 응답이면 App을 열지 않는다.
- 요청 1회는 본문 해석을 포함해 20초. 실패 후 10초 간격으로 직렬 재시도하며 최대 18회 또는 전체 180초 중 먼저 도달한 제한에서 중단한다. 4xx(429 포함)는 반복하지 않는다. 네트워크/시간 초과, 5xx/DOWN, 예상 밖 응답을 안전한 안내로 구분한다. 원본 응답·오류는 표시하거나 기록하지 않는다.
- 준비 중 경과 시간·대기 취소를 제공한다. 취소/실패 뒤에는 다시 확인 버튼에 초점을 옮긴다. 수동 재시도는 별도의 제한된 실행이다. 취소·unmount는 진행 요청/대기 타이머를 중단하고 이전 실행의 늦은 결과를 무시한다.
- 준비 완료 뒤 자동 조회를 멈춘다. 주기적 재검사, 자동 새로고침, 사용 중인 App의 강제 재마운트는 하지 않는다. 기존 로그인·계정별 동의·Extension capability·ACK·AI 요청별 동의는 그대로다.
- 비밀번호 POST, OAuth, 풀이 쓰기/동기화/공유/댓글/AI 요청을 이 재시도에 넣지 않는다. Extension 수집·IndexedDB·로컬 열람은 Dashboard/API와 독립이다.

## 검증과 남은 승인 항목

2026-08-31 19:24 KST에 초기 2분 버전 `c9a372a`의 Dashboard 배포가 live가 되었다(`dep-daalcq8ae00c73a7jiog`). API/Analysis 배포·설정은 바꾸지 않았다. 공개 HTML/JS/CSS는 모두 200이며 JS에 새 준비 화면/health 경로가 포함됨을 확인했다. 실제 Chrome 새 탭은 2분 제한 안내로 종료한 뒤 수동 재시도에서 입장 화면으로 복구했고, 즉시 새로고침은 1.023초였다. 비밀번호 입력/로그인은 수행하지 않았다.

같은 API의 시작 완료 로그는 09:47:17 UTC에 122.201초, 10:28:08 UTC에 125.797초를 기록했다. 실제 서버 재기동이 긴 대기에 기여한 근거다. 이를 반영한 3분 버전에는 126초 뒤 정상 응답이 성공하는 회귀 테스트를 추가했다. 유휴 종료가 모든 간헐 오류의 유일한 원인이라는 뜻은 아니며, 3분도 성공을 보장하는 무제한 대기가 아니다. **이 후속 3분 버전은 별도 배포 전까지 live 2분 버전과 구분한다.**

- 초기 2분 버전: Web TypeScript 검사, 전체 254개 테스트 통과(준비 조회/화면 26개 추가). 요청/본문 timeout, 총 제한, 반복 실패/4xx, 취소, 늦은 결과, StrictMode cleanup, 기존 입장 승인 및 계정/Extension 효과 차단, 기존 로그아웃/동의 회귀 포함.
- 실제 Chrome의 로컬 합성 화면에서 초기 지연 → 취소 → 늦은 응답 무시 → 수동 재시도 → 입장 화면 → 합성 승인 흐름 확인. 404 오류 안내 및 503 이후 정상 health 재시도도 확인했다. 외부 연결은 CSP로 차단하고 실제 API 호출 대신 주입한 합성 응답만 사용했다. 검증 화면은 빌드/커밋에서 제외한다.
- 이번 수정은 시작 시점만 보완한다. 이미 열린 탭이 장시간 유휴인 경우, 입장 폼에 오래 머문 후의 POST 지연, 이후 세션/DB/네트워크 실패는 각 기능의 오류 안내를 유지한다. 쓰기 요청의 자동 반복으로 덮지 않는다.
