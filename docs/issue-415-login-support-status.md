# Issue #415 — 확장 로그인 복귀와 상태형 문의

2026-10-09 사용자 결정으로 #413의 채팅·문의 종료·삭제·종료 90일 자동 정리를 대체합니다. 상태는 접수됨/확인중/답변완료이며, 일반 사용자는 접수와 상태/단일 관리자 답변 조회만 합니다. 서버가 검증한 관리자는 전체 문의함으로 바로 진입해 상태와 답변을 관리합니다. 탭은 주 메뉴 맨 오른쪽입니다.

## 범위와 승인 경계

- `apps/dashboard`: 문의 UI/API 타입·클라이언트·탭 순서, 로그인 문서 nonce.
- `apps/extension`: 로그인 복귀 정보 선저장·문서 응답·탭/창 복귀. 캡처/IndexedDB/자동 전송 계약은 변경하지 않습니다.
- `apps/api`: 문의 상태/단일 답변, 폐기 API 410, 삭제 경로 제거, V29 상태 제약 확장.
- `docs`: 실제 변경되는 로그인·문의·개인정보 계약만 갱신합니다.

세션·CSRF·예상 계정 헤더·immutable 관리자 GitHub ID·다른 사용자 404·rate limit·no-store를 유지합니다. 새 브라우저 권한, 자격 증명 저장, OAuth redirect origin, 외부 배포 또는 운영 데이터 변경은 없습니다.

## 호환성과 위험

V28을 수정하지 않고 V29를 추가합니다. V29는 기존 행/메시지/종료 시각을 삭제하거나 다시 쓰지 않습니다. 과거 CLOSED 행은 재확인 대상으로 OPEN을 표시하고 관리자 명시 처리 전까지 저장 상태는 유지합니다. 답변 수정은 최신 관리자 답변 한 건을 갱신하며 과거 메시지는 보존합니다.

API/V29를 먼저 적용하지 않은 서버는 IN_REVIEW를 거절하고 이전 삭제 정책을 여전히 가질 수 있습니다. 새 UI만 배포해 서버 기능이 바뀌었다고 안내하지 않습니다. develop PR 검증, 별도 승인된 API 적용, 로컬 확장 패키지 반영, 실제 Chrome 사용자/관리자 확인, develop → master 출시 승격을 구분합니다. Netlify/스토어 배포는 이 변경의 실행 범위가 아닙니다.

사용자가 제공한 이전 명세 파일 4개는 현재 develop에서 존재하지 않으므로 기존 작업 공간의 명세를 참조했습니다. 현재 구현은 `apps/dashboard` 및 Maven/Java 17 소스 타깃이며 이전 명세의 `apps/web`·Gradle/Java 21과 차이가 있습니다. 실행 검증은 설치된 JDK 21을 사용하되 프레임워크/빌드 기준은 이 기능 작업에서 변경하지 않습니다.

## 수용 확인

- 저장된 로그인 복귀 route보다 빠른 OAuth 완료가 발생하지 않음.
- Tab.url 누락에서도 원래 문서의 nonce 확인 후 탭/창 복귀.
- nonce 불일치/만료/다른 탭·origin/문서 이동/중복 이벤트는 잘못된 복귀나 중복 종료를 만들지 않음.
- 일반 웹 로그인 유지, 성공/실패 및 GitHub 설치 결과의 고정 필드만 전달; OAuth code/state/쿠키 전달 없음.
- 관리자 바로 문의함/상태 선택/단일 답변, 일반 사용자 읽기와 접수만, 마지막 탭 순서.
- 구 클라이언트 후속 메시지/종료/삭제 410, CLOSED/close=true 거부, 오래된 문의 접근 시 보존.
- 계정 전환/401/409/늦은 read·write 응답의 개인 데이터 및 관리자 권한 차단.
- PostgreSQL V28 → V29 기존 행·메시지 보존과 IN_REVIEW 저장 확인.

실제 Chrome OAuth와 배포된 상태형 문의 수용은 승인된 API 적용과 확장 로드 후 수행합니다. 단위 테스트를 실제 Chrome 수용으로 대신 표시하지 않습니다.
