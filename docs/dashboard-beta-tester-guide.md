# CodeArchive 사용 가이드

SWEA 풀이를 내 Chrome에 모으고, 원할 때 Dashboard로 옮겨 관리하는 출시 전 베타입니다. 설치는 [설치·업데이트 안내](beta-install.md), 배포 담당자의 검증은 [운영자 점검표](beta-distribution-checklist.md)를 따릅니다. 문서가 있다고 실사용 검증이 끝난 것은 아닙니다.

## 설치 전

- 운영자가 제공한 검증 커밋, Extension ZIP의 SHA-256, 실제 배포 버전을 확인합니다. ZIP은 Chrome 웹 스토어 배포가 아닌 압축 해제 설치용입니다.
- 기존 설치를 제거하지 마세요. 로컬 기록이 사라질 수 있습니다. 먼저 로컬 아카이브에서 필요한 기록을 내보내고, 기존 확장 프로그램을 갱신하는 방식으로 진행합니다.
- 테스트는 본인 소유 또는 전송에 동의한 코드만 사용하세요. 다른 사람의 코드, 비밀 키, 개인정보를 포함하지 마세요.

## 어디에서 무엇을 하나요?

| 화면 | 하는 일 | 데이터 위치 |
| --- | --- | --- |
| Extension 팝업 → **로컬 풀이 보기** | 수집 확인·로컬 조회·수정·내보내기·삭제 | 현재 Chrome 프로필 |
| Extension 팝업 → **전체 풀이 보기** | 웹 Dashboard 열기 | 아래 Dashboard로 이동 |
| 웹 Dashboard | GitHub 로그인·동의 기반 동기화·서버 풀이 관리·AI | 로그인한 계정의 서버 보관함 |

로컬 목록과 서버 목록은 서로 다른 사본입니다. 서버에서 수정/삭제한다고 로컬 원본이 바뀌지 않습니다. 로그인하지 않아도 로컬 수집과 조회는 사용할 수 있습니다. 로컬 **파일 가져오기**와 **새 풀이 등록**은 수동 기록 기능이며 모든 수동 기록이 자동 동기화 대상이라고 가정하지 마세요.

현재 전환 단계에는 이전 Extension 인증/API 코드와 권한이 남아 있습니다. 로그인과 서버 동기화·AI는 Dashboard를 이용하세요. 이 잔여 코드는 실제 대체 흐름 검증 후 별도 작업(#86)으로 제거합니다. 로컬 아카이브는 오프라인 대체 수단으로 유지됩니다.

## 첫 풀이로 확인하기

1. SWEA에서 정답 제출 후 Extension의 로컬 기록을 확인합니다. Dashboard가 닫혀 있거나 서버가 응답하지 않아도 로컬 저장은 유지되어야 합니다. 실행시간·메모리는 자동 수집하지 않으며 필요할 때 직접 입력합니다.
2. [Dashboard 베타](https://codearchive-dashboard-beta.onrender.com)를 열어 초대받은 비밀번호로 **Dashboard 입장**을 누릅니다. 같은 탭에서는 새로고침·GitHub 로그인 후 복귀에도 다시 묻지 않습니다. 이후 **GitHub로 로그인**하고 화면의 계정이 의도한 계정인지 확인합니다. 비밀번호 확인은 GitHub 로그인을 대신하지 않습니다.
3. **Extension 연결됨** 상태와 로컬 목록의 전송 대상을 확인하고, 준비되었을 때 **자동 동기화**를 직접 켭니다. **한 건을 선택해 보내는 기능이 아닙니다. 대기 중인 로컬 코드 전체**가 현재 로그인 계정의 서버 보관함으로 전송될 수 있습니다. 민감한 기록이 섞여 있다면 켜지 말고 로컬 기능만 사용하세요.
4. 동기화 동의는 이 브라우저의 같은 계정에서 기억됩니다. 끄기·로그아웃·계정 변경 시 해제됩니다. 새 계정에서는 다시 동의해야 합니다.
5. Dashboard에서 검색·풀이 상세·수정·코드 복사·Source/Markdown 다운로드를 사용합니다. 서버 수정은 로컬 원본을 변경하지 않습니다.
6. **서버에서 삭제**는 확인 후 수행하며 되돌릴 수 없습니다. 로컬 원본과 동기화 확인 기록은 유지됩니다. 아직 대기 중인 원본은 나중에 서버에 다시 저장될 수 있습니다.
7. **AI 도우미 열기**에서 저장된 결과를 확인합니다. 접근 방법 설계·주석 코드 생성·코드 리뷰 중 하나를 고르고 전송 설명에 동의한 뒤 실행합니다. 결과는 원본과 별도로 저장됩니다.

AI 결과는 틀릴 수 있습니다. `fake`로 표시된 결과는 실제 AI 분석이 아닌 테스트 결과입니다. AI 요청이 끝나지 않거나 오류가 보이면 결과를 새로고침해 확인한 후 재시도하세요. 서버는 계속 처리 중일 수 있고 요청 한도가 차감되었을 수 있습니다. 자동으로 재요청하지 않습니다.

## 평소 사용과 데이터 보존

- Dashboard 탭이 열려 있고 로그인·동의·연결이 유효하면 새 수집 기록이 자동으로 전송됩니다. 닫힌 동안은 로컬에 쌓이고 다음 연결 때 따라잡습니다. 잠든 PC에서 계속 수집/전송되는 기능은 아닙니다.
- 전송을 멈추려면 **자동 동기화**를 끕니다. 로그아웃·계정 변경 뒤에는 새 계정을 확인하고 다시 동의합니다. 같은 Chrome 프로필의 로컬 기록은 서버 계정별 보관함과 같지 않습니다.
- Dashboard 목록이 늦게 바뀌면 **목록 새로고침**으로 확인합니다. 로그인 계정과 pending 상태부터 확인하고 같은 기록을 반복 업로드하지 않습니다.
- 중요한 풀이마다 **Source**로 코드 파일, **Markdown**으로 읽기용 문서를 보관합니다. **코드 복사**는 클립보드로 복사할 뿐 파일 백업이 아닙니다.
- 전체 일괄 백업·내부 ID/동기화 상태까지 복원하는 기능은 없습니다. [업데이트 전 보존 절차](beta-install.md)를 확인하세요.
- 삭제는 테스트용 사본에서만 연습하세요. **서버에서 삭제**로 지운 서버 기록은 되돌릴 수 없습니다. 이미 동기화 확인된 로컬 원본이 자동으로 다시 올라오는 복원 기능도 아닙니다.
- 자동 동기화와 AI 생성 동의는 별개입니다. 실제 provider가 활성화된 뒤의 AI 요청은 안내된 외부 처리 범위를 읽고 작업마다 동의하세요. 현재 `fake` 상태를 실제 AI 결과 품질로 평가하지 않습니다.

## 오류가 나면

- 로컬 기록부터 확인하고 보존합니다. Extension을 제거하거나 브라우저 저장소를 지우지 않습니다.
- 연결이 안 되면 Extension ID와 Dashboard 주소를 확인하고 **다시 확인**을 누릅니다.
- 로그인 확인 오류에는 **다시 시도**, 목록 오류에는 **다시 불러오기**를 사용합니다. 무료 서비스가 깨어나는 데 시간이 걸릴 수 있습니다.
- 동기화 대기 수가 줄지 않아도 기록을 반복 삭제하거나 다른 계정으로 무작정 재전송하지 마세요. 부분 실패 시 성공한 항목만 확인 처리되어야 합니다.
- 보고할 내용: 발생 시각, Chrome 버전, 패키지 버전/해시, 진행 단계, 기대 결과/실제 결과, 민감정보를 가린 화면. 코드·토큰·쿠키·OAuth 콜백 주소·개인정보는 첨부하지 않습니다.

상세한 증상별 대처와 복사 가능한 제보 양식은 [문제 해결·오류 제보](beta-troubleshooting.md)에 있습니다. 운영자 승인·두 계정 E2E·배포 기록은 [별도 점검표](beta-distribution-checklist.md)에서 관리합니다.

현재 베타의 필수 범위는 SWEA, GitHub 로그인, 계정별 서버 보관, 로컬 보존, AI 3종입니다. GitHub 저장소 업로드, 공개 공유·순위표, 통계·추천, 다른 문제 플랫폼과 웹 스토어 출시는 이번 완료 조건에 포함하지 않습니다.
