# CodeArchive 소규모 베타 안내

이 문서는 Issue #31의 약 20명 SWEA 베타용입니다. 현재 코드는 배포·실사용 승인 전 후보이며, 아래 운영자 점검표가 끝나기 전에는 검증 완료된 배포본으로 안내하지 않습니다.

## 설치 전

- 운영자가 제공한 검증 커밋, Extension ZIP의 SHA-256, 실제 배포 버전을 확인합니다. ZIP은 Chrome 웹 스토어 배포가 아닌 압축 해제 설치용입니다.
- 기존 설치를 제거하지 마세요. 로컬 기록이 사라질 수 있습니다. 먼저 로컬 아카이브에서 필요한 기록을 내보내고, 기존 확장 프로그램을 갱신하는 방식으로 진행합니다.
- 테스트는 본인 소유 또는 전송에 동의한 코드만 사용하세요. 다른 사람의 코드, 비밀 키, 개인정보를 포함하지 마세요.

## Chrome에 설치

1. ZIP을 계속 유지할 전용 폴더에 압축 해제합니다.
2. Chrome 주소창에 `chrome://extensions`를 입력하고 개발자 모드를 켭니다.
3. **압축해제된 확장 프로그램을 로드합니다**에서 `manifest.json`이 있는 폴더를 선택합니다. 기존 설치 사용자는 운영자의 갱신 안내를 따릅니다.
4. 확장 프로그램 ID가 `oohlcmihldmfninmdcmanddfmhoonmdl`인지 확인합니다. 다른 ID이거나 오류가 나오면 동기화하지 말고 운영자에게 문의합니다.
5. 기존에 열려 있던 SWEA 탭은 새로고침합니다. 확장 프로그램 폴더는 삭제하거나 이동하지 않습니다.

현재 전환 단계에는 이전 Extension 인증/API 코드와 권한이 남아 있습니다. 로그인과 서버 동기화·AI는 Dashboard를 이용하세요. 이 잔여 코드는 실제 대체 흐름 검증 후 별도 작업(#86)으로 제거합니다. 로컬 아카이브는 오프라인 대체 수단으로 유지됩니다.

## 사용 순서

1. SWEA에서 정답 제출 후 Extension의 로컬 기록을 확인합니다. Dashboard가 닫혀 있거나 서버가 응답하지 않아도 로컬 저장은 유지되어야 합니다. 실행시간·메모리는 자동 수집하지 않으며 필요할 때 직접 입력합니다.
2. [Dashboard 베타](https://codearchive-dashboard-beta.onrender.com)를 열어 GitHub로 로그인합니다. 화면의 계정이 의도한 계정인지 확인합니다.
3. **Extension 연결됨** 상태를 확인하고, 전송할 준비가 되었을 때 **자동 동기화**를 직접 켭니다. 대기 중인 로컬 코드가 현재 로그인 계정의 서버 보관함으로 전송됩니다.
4. 동기화 동의는 이 브라우저의 같은 계정에서 기억됩니다. 끄기·로그아웃·계정 변경 시 해제됩니다. 새 계정에서는 다시 동의해야 합니다.
5. Dashboard에서 검색·풀이 상세·수정·코드 복사·Source/Markdown 다운로드를 사용합니다. 서버 수정은 로컬 원본을 변경하지 않습니다.
6. **서버에서 삭제**는 확인 후 수행하며 되돌릴 수 없습니다. 로컬 원본과 동기화 확인 기록은 유지됩니다. 아직 대기 중인 원본은 나중에 서버에 다시 저장될 수 있습니다.
7. **AI 도우미 열기**에서 저장된 결과를 확인합니다. 접근 방법 설계·주석 코드 생성·코드 리뷰 중 하나를 고르고 전송 설명에 동의한 뒤 실행합니다. 결과는 원본과 별도로 저장됩니다.

AI 결과는 틀릴 수 있습니다. `fake`로 표시된 결과는 실제 AI 분석이 아닌 테스트 결과입니다. AI 요청이 끝나지 않거나 오류가 보이면 결과를 새로고침해 확인한 후 재시도하세요. 서버는 계속 처리 중일 수 있고 요청 한도가 차감되었을 수 있습니다. 자동으로 재요청하지 않습니다.

## 오류가 나면

- 로컬 기록부터 확인하고 보존합니다. Extension을 제거하거나 브라우저 저장소를 지우지 않습니다.
- 연결이 안 되면 Extension ID와 Dashboard 주소를 확인하고 **다시 확인**을 누릅니다.
- 로그인 확인 오류에는 **다시 시도**, 목록 오류에는 **다시 불러오기**를 사용합니다. 무료 서비스가 깨어나는 데 시간이 걸릴 수 있습니다.
- 동기화 대기 수가 줄지 않아도 기록을 반복 삭제하거나 다른 계정으로 무작정 재전송하지 마세요. 부분 실패 시 성공한 항목만 확인 처리되어야 합니다.
- 보고할 내용: 발생 시각, Chrome 버전, 패키지 버전/해시, 진행 단계, 기대 결과/실제 결과, 민감정보를 가린 화면. 코드·토큰·쿠키·OAuth 콜백 주소·개인정보는 첨부하지 않습니다.

## 운영자 최종 점검표

각 항목은 실제 수행 후에만 체크합니다. 로컬 모의 테스트나 GitHub CI는 아래 실사용 검증을 대신하지 않습니다.

- [ ] Render의 정확한 작업공간·서비스 확인, auto-deploy 비활성, 유료 자원 추가 없음
- [ ] 승인받은 정확한 `develop` 커밋을 베타에 배포하고 Dashboard/API/Analysis별 실제 SHA 기록
- [ ] 두 개의 서로 다른 GitHub 계정 준비, 테스트 코드 전송 동의, 합성 테스트 데이터만 사용
- [ ] 실제 SWEA 정답 → Dashboard 닫힘 상태에서도 로컬 저장
- [ ] 정확한 HTTPS origin 연결, 로그인 전·동의 전 코드 전송 없음
- [ ] 로그인·명시적 자동 동기화 동의 후 신규 기록 자동 저장
- [ ] 연결 종료 동안 쌓인 기록이 재연결 후 저장되고 중복 기록 없음
- [ ] 부분 실패에서 성공/중복 항목만 ACK, 모든 로컬 원본 유지
- [ ] 로그아웃·계정 변경 즉시 이전 전송 중단, 다른 계정의 풀이·AI 결과 접근 차단
- [ ] [AI 배포 검증](dashboard-ai-beta-acceptance.md)의 세 작업·권한·오류·원본 보존 점검
- [ ] 별도 승인된 재시작/재배포 후 PostgreSQL 풀이·결과 유지 확인
- [ ] 민감정보 로그 없음, 장애 대응·롤백 커밋 기록
- [ ] 대체 E2E 통과 후 #86 범위의 기존 인증/API/AI·불필요 권한 정리 및 재검증
- [ ] 검증된 패키지와 안내를 약 20명에게 배포할 준비 완료

현재 베타의 필수 범위는 SWEA, GitHub 로그인, 계정별 서버 보관, 로컬 보존, AI 3종입니다. GitHub 저장소 업로드, 공개 공유·순위표, 통계·추천, 다른 문제 플랫폼과 웹 스토어 출시는 이번 완료 조건에 포함하지 않습니다.
