# 본인 제출 누락 대조·보강 (#324, #325)

과거 풀이 수집에서 SWEA/프로그래머스 후보 찾기를 완료한 뒤 `누락 풀이 대조`를 실행한다. 본인 제출 키·문제·언어·제출 시각을 로컬/서버와 대조한다. 서버 목록은 로그인 계정을 처음과 마지막에 확인하고 50건씩 최대 5,000건 조회한다. 응답은 코드 원문 없이 SHA-256 및 제출 메타데이터만 전달한다. 서버 오류나 계정 변경은 서버 누락으로 표시하지 않는다.

상태: 제출 키 기준 일치 / 로컬 누락 / 서버 누락 / 보강 가능 / 대조 불일치 / 확인 불가. 실제 복구는 선택한 제출의 본인·정답·원본 코드·제출 시각을 다시 확인한다. 같은 제출 키의 코드·언어·문제·시각이 다르면 덮어쓰지 않는다. 실시간 캡처처럼 제출 키가 없는 유사 항목도 임의 병합하지 않는다.

`기존 제출 정보 확인`은 이미 저장된 제출을 다시 검증하여 비어 있는 실행시간·메모리·난이도만 보강한다. 기존 코드, 제출 ID, 제출 시각 및 이미 있는 측정값을 보존한다. 서버에 이미 같은 제출이 있어도 보강 대기 항목은 일괄 동기화 대상으로 남는다. 서버 수락이 확인된 항목에만 ACK한다. 복구·보강은 자동 서버 업로드나 GitHub 커밋을 실행하지 않는다.

범위: 후보 목록을 끝까지 확인한 계정에 한정한다. SQL 제출 이력 미지원, 모호한 원본 소유권, 변형된 제출 키는 확인 불가/대조 불일치로 남긴다. 실제 SWEA/프로그래머스 계정의 복구·재실행 멱등성 검증은 완료 전 이슈에 기록한다.
