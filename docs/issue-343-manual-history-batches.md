# 과거 풀이 수동 일괄 처리 — #346 / #343

## 사용자 흐름

1. 확장 프로그램에서 정올·SWEA·프로그래머스의 과거 풀이를 로컬에 수집한다. CodeArchive 로그인은 필요하지 않다.
2. 대시보드에 로그인하고 **전체 풀이 → 과거 풀이 일괄 동기화 / GitHub 커밋**을 연다.
3. 동기화 플랫폼(전체 또는 한 사이트)과 제출을 선택해 **일괄 동기화**한다. 중복 판단은 현재 로그인 계정의 서버 제출 기록을 기준으로 한다. 로컬 저장은 유지하며 서버 수락 건만 동기화 표시한다.
4. 사이트별 동기화를 모두 마친 뒤 **GitHub 일괄 커밋**에서 서버 기록을 선택한다. 자동 커밋 설정이 꺼져 있어도 수동 요청할 수 있다.
5. **커밋 대상 확인**에서 계정·저장소·브랜치·경로와 문제/제출 수를 확인한 뒤 **GitHub 커밋 요청**을 누른다. 일괄 요청이지만 기존 작업 체계에 따라 제출마다 별도 커밋을 만든다. 하나의 Git 커밋으로 모든 파일을 묶는 기능은 아니다.

## 상태와 재시도

- 동기화의 개별 거절은 다음 제출/플랫폼 처리를 막지 않는다. 실패 항목의 선택은 유지한다.
- 네트워크·계정·연결 확인 실패 시 추가 쓰기를 멈춘다. 새로고침으로 서버 상태를 확인한 뒤 남은 항목만 재시도한다.
- 동기화 중단은 현재 업로드의 수락 확인·ACK를 마친 뒤 적용한다.
- 커밋 완료·대기·진행 중·결과 확인 필요 상태는 새 요청 대상으로 선택하지 않는다.
- 확정된 FAILED만 명시적 요청으로 재시도한다. UNKNOWN은 GitHub에서 결과를 확인해야 한다.
- 명시적 재시도는 영속적인 delivery_generation을 증가시켜 Cloud Tasks의 이전 작업 이름과 구분한다. 같은 재시도 요청의 반복은 새 세대를 만들지 않는다.
- 화면을 닫거나 다른 대시보드 탭으로 이동해도 컴포넌트와 진행 중인 작업을 유지한다. 브라우저 페이지 자체를 닫으면 추가 요청은 중단되며, 이미 서버에 접수된 커밋은 서버에서 계속 처리한다.
- 커밋 진행률은 요청 접수 수가 아니라 서버에서 확인한 SUCCEEDED 수를 사용한다.

## 적용과 검증

- API에 V19(제출 ID 길이 확장), V20(수동 재시도 전달 세대) 마이그레이션이 필요하다. 운영 DB에 직접 적용하거나 설정을 추측하지 않는다.
- 확장 업데이트와 API/대시보드 배포를 함께 적용해야 한다. 이번 구현 작업 자체는 배포하지 않는다.
- 실제 확장 연결, 사용자 계정의 서버 업로드 및 GitHub 커밋은 배포 후 별도로 검증한다. 자동 테스트나 아래 테스트 데이터 결과를 실제 업로드 결과로 보고하지 않는다.
- #324 SWEA 로컬 수집은 사용자가 문제 11건/제출 11건 신규 저장을 확인하고 완료로 승인했다. #324의 전체 서버 누락 대조 범위는 이 결과와 별도로 관리한다.

### 2026-10-06 Chrome 사전 검증

`apps/dashboard`에서 `node test/history-browser-fixture.mjs`를 실행하고
`http://127.0.0.1:5178`을 Chrome으로 열었다. 실제 App, 동기화/커밋 컴포넌트,
API 클라이언트를 사용하며 확장 응답과 서버는 합성 데이터로 대체한다.
모든 API 경로를 로컬에서 처리하므로 실제 풀이·인증 정보·GitHub를 사용하지 않는다.

- 정올 54건, SWEA 2건, 프로그래머스 2건 중 서버 중복 3건이 처음부터 선택에서 제외됐다.
- SWEA만 선택해 1건을 동기화하고 연동 가이드로 이동한 뒤 돌아와 완료 상태를 확인했다.
- 전체에서 54건을 시작하고 중단·화면 닫기를 실행했다. 진행 중인 50건 응답에서 49건만 수락·ACK됐고, 거절 1건과 미처리 4건의 선택이 유지됐다.
- 남은 5건을 재시도하면서 다른 메뉴로 이동했다. 최종 서버 동기화 58건, 신규 ACK 55건을 확인했다. 업로드 요청 크기는 1, 50, 4, 1건이었다.
- GitHub 자동 커밋 OFF 상태에서 계정·저장소·브랜치·경로 미리보기를 확인했다. 완료 및 UNKNOWN 2건을 제외한 56건을 명시적으로 요청했다.
- 요청 크기는 50, 6건이었고, 화면을 닫거나 이동해도 계속 처리됐다. 완료 진행률 56/56, 기존 완료 포함 57건, UNKNOWN 1건을 확인했다. 재요청 버튼은 비활성화됐다.

이 결과는 브라우저 UI와 요청/응답 흐름 검증이다. 실제 확장 및 배포된 API/worker의 업로드·GitHub 결과 검증은 별도 단계다.
