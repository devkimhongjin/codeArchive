## 1. 프로젝트 개요

### 1.1 프로젝트명

CodeArchive

SWEA, 프로그래머스, 정올, LeetCode에서 풀이한 코딩테스트 문제를 자동으로 기록하고, 기존 풀이 가져오기, AI 활용도 관리, AI 코드 리뷰, 소스 파일 내보내기, Notion 정리, GitHub 업로드, 복습 관리까지 지원하는 크롬 확장 프로그램이다.

### 1.2 개발 배경

코딩테스트를 준비하는 사용자는 여러 알고리즘 문제 풀이 플랫폼을 이용한다. 그러나 문제 정보, 제출 코드, 오답 이력, 풀이 과정이 플랫폼별로 분산되어 있어 체계적인 관리가 어렵다.

문제를 푼 후 기록을 남기기 위해서는 다음과 같은 반복 작업이 필요하다.

- 문제 제목과 번호 복사
- 문제 링크와 난이도 기록
- 제출 코드 복사
- 사용 언어와 실행 결과 기록
- 풀이 과정과 시간 복잡도 작성
- 소스 파일 생성
- README 작성
- GitHub 커밋
- Notion 페이지 생성
- 복습 일정 등록
또한 생성형 AI가 코딩 학습에 활용되면서 단순히 문제를 풀었는지만 기록하는 것으로는 학습 과정을 정확하게 평가하기 어려워졌다.

같은 정답 문제라도 다음과 같은 차이가 있을 수 있다.

- AI를 전혀 사용하지 않고 혼자 해결
- 문법이나 개념만 검색
- 힌트만 받아 해결
- 오류 원인만 AI에게 질문
- 풀이 방향을 AI에게 제안받음
- AI가 생성한 코드를 참고하여 수정
- 전체 풀이를 AI에게 맡긴 후 코드를 분석하며 학습
따라서 문제별로 AI를 어느 정도 사용했는지, 어떤 목적으로 사용했는지, AI의 도움 없이 다시 풀 수 있는지를 기록할 필요가 있다.

본 프로젝트는 문제 풀이 기록 자동화뿐 아니라 사용자의 실제 문제 해결 과정과 AI 의존도를 함께 관리하여, 자신의 순수 문제 해결 능력과 AI 활용 능력을 구분해서 확인할 수 있는 학습 환경을 제공하는 것을 목표로 한다.

## 3. 지원 플랫폼 우선순위

플랫폼 지원 순서는 다음과 같다.

SWEA

    → 프로그래머스
    → 정올
    → LeetCode
### 3.1 1순위: SWEA

초기 개발과 검증의 중심 플랫폼으로 선정한다.

주요 이유는 다음과 같다.

- 국내 알고리즘 교육 과정에서 사용 빈도가 높음
- Java 기반 풀이 비중이 높음
- 문제 번호와 난이도 체계가 명확함
- 전체 실행 코드 형태가 많음
- 소스 파일 내보내기 검증에 적합함
- 제출 결과와 테스트 케이스 기반 기록 수요가 높음
초기 구현 범위는 다음과 같다.

- 문제 페이지 감지
- 문제 번호, 제목, 난이도 수집
- 제출 코드 수집
- 제출 결과 감지
- Java 소스 파일 내보내기
- 기존 수동 기록과 자동 기록 병합
### 3.2 2순위: 프로그래머스

- 국내 기업 코딩테스트 준비 과정에서 활용도가 높음
- 함수형 제출 코드 수집 가능
- Java, Python, JavaScript 등 다국어 지원 필요
- GitHub 포트폴리오 연동 수요가 높음
- 문제 제목과 난이도 기반 기록 관리에 적합함
### 3.3 3순위: 정올

- 기초 구현, 배열, 탐색 문제 관리에 적합함
- 문제 번호 중심의 기록 구조를 검증할 수 있음
- Main 클래스 기반 파일 저장 기능이 필요함
- 교육 과정별 문제 관리 기능으로 확장 가능함
### 3.4 4순위: LeetCode

- 영문 문제와 글로벌 알고리즘 학습 기록 지원
- Easy, Medium, Hard 난이도 활용
- 공식 알고리즘 태그 활용
- 다국어 풀이 관리
- 동일 문제를 여러 언어로 풀이하는 학습 방식 지원
### 3.5 플랫폼 어댑터 구조

    interface PlatformAdapter {
    isProblemPage(): boolean;
    getProblemInfo(): Promise<ProblemInfo>;
    getSourceCode(): Promise<string>;

각 플랫폼의 DOM 구조가 변경되더라도 다른 기능에 영향을 최소화할 수 있도록 플랫폼별 어댑터를 분리한다.

## 4. 주요 사용자

### 4.1 주요 대상

- 코딩테스트를 준비하는 취업 준비생
- 알고리즘 문제를 꾸준히 풀이하는 학생
- SWEA와 프로그래머스를 중심으로 학습하는 사용자
- AI를 활용해 코딩 공부를 하는 사용자
- AI 의존도를 줄이고 싶은 사용자
- 풀이 기록을 Notion에 정리하는 사용자
- 알고리즘 코드를 GitHub에 저장하는 사용자
- 여러 언어로 동일 문제를 다시 푸는 사용자
- 기존 풀이 기록을 통합하고 싶은 사용자
### 4.2 신규 문제 풀이 시나리오

1. 사용자가 SWEA에서 문제를 푼다.
2. 코드를 제출한다.
3. 확장 프로그램이 제출 결과를 감지한다.
4. 문제 정보와 제출 코드를 자동으로 수집한다.
5. 기록이 로컬 데이터베이스에 저장된다.
6. 사용자가 풀이 과정과 오답 원인을 작성한다.
7. 문제 풀이 과정에서 사용한 AI 활용 수준을 선택한다.
8. 필요한 경우 AI 코드 리뷰를 실행한다.
9. 풀이 언어에 맞는 소스 파일로 저장한다.
10. Notion에서 정리하거나 GitHub에 업로드한다.
11. AI 도움을 많이 받은 문제는 복습 대상으로 등록한다.
### 4.3 기존 문제 추가 시나리오

1. 사용자가 기존 풀이 추가 를 선택한다.
2. 문제 URL, 코드, 소스 파일, Markdown 또는 JSON을 입력한다.
3. 서비스가 플랫폼과 문제 정보를 추정한다.
4. 풀이 당시 AI 활용 수준을 선택한다.
5. 기존 기록과 중복 여부를 검사한다.
6. 사용자가 내용을 검토한다.
7. 기존 문제와 병합하거나 새로운 기록으로 저장한다.

## 6. 문제 정보 및 제출 기록 자동 수집

### 6.1 플랫폼 자동 인식

현재 페이지의 URL과 DOM 구조를 분석하여 다음 페이지를 구분한다.

- 문제 페이지
- 코드 작성 페이지
- 제출 결과 페이지
- 제출 이력 페이지
- 해결 문제 목록
- 사용자 마이페이지
지원하지 않는 페이지에서는 자동 수집을 비활성화한다.

### 6.2 문제 정보 수집

- 플랫폼
- 문제 고유 ID
- 문제 번호
- 문제 제목
- 문제 URL
- 난이도
- 공식 알고리즘 태그
- 제한 조건
- 수집 시각
플랫폼에서 직접 제공하지 않는 정보는 비워 두거나 사용자가 직접 입력한다.

### 6.3 제출 결과 감지

- 정답
- 틀렸습니다.
- 시간 초과
- 메모리 초과
- 런타임 에러
- 컴파일 에러
- 출력 형식 오류
- 부분 점수
- 실행 시간
- 메모리 사용량
- 제출 언어
- 제출 일시
결과가 비동기적으로 표시되는 플랫폼에서는 MutationObserver 를 사용한다.

### 6.4 제출 코드 수집

- 코드 편집기 내용 읽기
- 제출 언어 감지
- 정답 코드 저장
- 오답 코드 선택 저장
- 제출별 코드 버전 관리
- 이전 코드와 최종 코드 비교
- 동일 문제의 여러 언어 풀이 관리
1차 제출: 컴파일 에러 2차 제출: 시간 초과 3차 제출: 틀렸습니다. 4차 제출: 정답

## 8. 문제별 AI 활용 기록

### 8.1 기능 목적

정답 여부만으로는 사용자의 실제 문제 해결 능력을 정확히 평가하기 어렵다.

AI를 전혀 사용하지 않고 해결한 문제와 AI가 생성한 전체 풀이를 참고한 문제를 동일한 정답 문제로 처리하면 다음 문제가 발생한다.

- 사용자가 실제로 이해한 문제 수를 파악하기 어려움
- AI 없이 다시 풀어야 할 문제를 놓칠 수 있음
- 취약한 알고리즘 유형이 통계에서 가려질 수 있음
- 학습 과정과 포트폴리오 기록의 신뢰도가 떨어질 수 있음
- AI 활용 습관이 개선되고 있는지 확인하기 어려움
따라서 각 문제마다 AI 활용 정도와 활용 목적을 기록한다.

### 8.2 AI 활용 수준

AI 활용 수준은 다음 단계로 구분한다.

Level 0: AI 미사용

문제 풀이 과정에서 AI를 전혀 사용하지 않았다.

포함되는 경우:

- 문제를 혼자 읽고 해결
- 공식 언어 문서나 일반 검색도 사용하지 않음
- 기존에 알고 있던 개념만 사용
표시명:

AI 미사용

Level 1: 개념·문법 검색

문제의 직접적인 풀이를 요청하지 않고 개념이나 문법만 확인했다.

예시:

- Java에서 우선순위 큐 사용하는 방법
- DFS와 BFS의 차이
- StringTokenizer 사용법
- 정수 범위 확인
- 특정 라이브러리 메서드 사용법
표시명:

개념·문법만 참고

Level 2: 부분 힌트 사용

정답 코드나 전체 풀이 없이 문제 해결에 필요한 작은 힌트만 받았다.

예시:

- 어떤 알고리즘 유형인지 질문
- 반례 한 개 요청
- 접근 방향이 맞는지 확인
- 시간 복잡도 개선 힌트 요청
- 현재 코드의 오류 위치만 질문
표시명:

부분 힌트 사용

Level 3: 풀이 방향 도움

AI에게 전체적인 풀이 전략이나 알고리즘 접근을 설명받았지만 코드는 직접 작성했다.

예시:

- 문제 해결 단계 설명 요청
- 적절한 자료구조 추천
- 알고리즘 설계 방법 요청
- 의사 코드 참고
- 풀이 아이디어를 받은 후 직접 구현
표시명:

풀이 방향 도움

Level 4: 코드 일부 참고

AI가 작성하거나 수정한 코드 일부를 참고하여 최종 코드를 완성했다.

예시:

- 특정 메서드 구현 요청
- 오류가 있는 부분의 수정 코드 참고
- 시간 초과 부분의 개선 코드 참고
- 입력 처리 코드 복사
- 전체 코드 중 일부 로직 활용
표시명:

코드 일부 참고

Level 5: 전체 풀이 참고

AI에게 전체 풀이 또는 완성 코드를 요청하고, 이를 참고하여 제출했다.

사용자가 일부 수정했더라도 문제 해결의 핵심 로직을 AI가 제공한 경우 포함한다.

표시명:

전체 풀이 참고

Level 6: AI 풀이 학습

문제 풀이를 AI에게 맡기고, 사용자는 생성된 풀이를 읽고 분석하며 공부하는 방식으로 사용했다.

이 단계는 독립적인 문제 해결 기록보다는 학습 기록으로 구분한다.

표시명:

AI 풀이로 학습

### 8.3 기본 선택 UI

문제 저장 시 다음 중 하나를 선택한다.

AI 미사용 개념·문법만 참고 부분 힌트 사용 풀이 방향 도움 코드 일부 참고 전체 풀이 참고 AI 풀이로 학습

빠른 기록을 위해 제출 완료 팝업에서는 한 번의 선택으로 저장할 수 있도록 한다.

사용자가 선택하지 않은 경우 다음 상태로 저장한다.

AI 활용 여부 미기록

### 8.8 AI 활용과 AI 코드 리뷰 구분

본 서비스에서 다음 두 개념은 별도로 관리한다.

문제 풀이 중 AI 활용

사용자가 실제 문제를 해결하는 과정에서 AI를 사용한 기록이다.

예시:

- 힌트를 받음
- 오류를 수정함
- 전체 풀이를 참고함
풀이 완료 후 AI 코드 리뷰

문제를 해결한 후 저장된 코드를 분석하기 위해 서비스의 AI 리뷰 기능을 사용한 기록이다.

풀이 완료 후 코드 리뷰를 실행했더라도, 문제를 혼자 해결했다면 AI 활용 수준은 AI 미사용 으로 유지할 수 있다.

따라서 다음 필드를 분리한다.

    interface SolutionRecord {

aiUsageDuringSolving: AIUsageRecord; postSolveAIReview?: AIReviewRecord;

    }
이를 통해 AI를 사용하지 않고 문제를 푼 뒤 코드 품질 검토만 AI에게 받은 경우를 정확하게 표현할 수 있다.

### 8.9 AI 활용 수준 자동 제안

사용자가 확장 프로그램 내부 AI 기능을 사용한 경우 해당 행동을 기반으로 AI 활용 수준을 제안할 수 있다.

예시:

- 개념 설명만 요청: 개념·문법만 참고 제안
- 반례 생성 요청: 부분 힌트 사용 제안
- 풀이 알고리즘 요청: 풀이 방향 도움 제안
- 수정 코드 생성: 코드 일부 참고 제안
- 전체 정답 코드 생성: 전체 풀이 참고 제안
자동 제안은 확정값이 아니며 사용자가 직접 수정한다.

외부 ChatGPT, Claude, Gemini 등을 사용한 기록은 사용자가 직접 입력한다.

### 8.10 AI 활용 기록 수정

사용자는 문제를 복습한 후 AI 활용 수준을 변경하지 않고, 새로운 독립 풀이 기록을 추가한다.

예시:

최초 풀이 - AI 활용: 전체 풀이 참고 - 이해도: 일부만 이해함

1차 복습 - AI 활용: 부분 힌트 사용 - 이해도: 직접 설명 가능

2차 복습 - AI 활용: AI 미사용 - 이해도: 변형 문제 적용 가능

최초 풀이 기록을 덮어쓰지 않고 학습 과정의 변화를 보존한다.

## 9. AI 활용 기반 복습 관리

### 9.1 복습 필요도 자동 제안

AI 활용 수준에 따라 복습 우선순위를 제안한다.

낮은 복습 우선순위

- AI 미사용
- 정답
- 직접 설명 가능
- AI 없이 다시 풀기 가능
중간 복습 우선순위

- 개념·문법만 참고
- 부분 힌트 사용
- 일부 예외 케이스에서 실수
- 코드 설명은 가능하지만 변형 적용이 어려움
높은 복습 우선순위

- 풀이 방향 도움
- 코드 일부 참고
- 전체 풀이 참고
- AI 풀이로 학습
- AI 없이 다시 풀기 어려움
- 핵심 로직 설명 불가능
복습 우선순위는 자동 제안하며 사용자가 수정할 수 있다.

### 9.2 AI 의존 문제 복습 모드

AI 도움을 많이 받은 문제는 기존 코드와 AI 답변을 숨긴 상태에서 다시 풀도록 한다.

복습 화면에는 다음 정보만 표시한다.

- 문제 제목
- 문제 원본 링크
- 난이도
- 이전 오답 원인
- 사용한 알고리즘 태그
- 최소 힌트
- 마지막 풀이 이후 경과 일수
사용자가 다시 제출한 후 다음 내용을 비교한다.

- 이전 AI 활용 수준
- 현재 AI 활용 수준
- 이전 코드와 현재 코드
- 제출 횟수 변화
- 해결 시간 변화
- 이해도 변화

- AI 미사용과 AI 활용 여부 미기록을 구분한다.
- 문제 풀이 중 AI 활용과 풀이 후 AI 코드 리뷰를 구분한다.
- AI 기여 비율, 이해도, 재풀이 가능 여부를 기록한다.
- AI 도움을 받은 문제의 복습 우선순위를 높인다.
- 복습 과정에서 AI 사용량이 줄어드는 변화를 확인한다.
- Notion은 회고와 복습 노트로 활용한다.
- GitHub는 코드와 포트폴리오 관리에 활용한다.
- AI 사용량이 아니라 AI 활용 후 학습 성과를 평가한다.

## 33. 결론

본 프로젝트는 SWEA, 프로그래머스, 정올, LeetCode에서 발생하는 코딩테스트 문제 풀이 기록을 자동으로 수집하고 관리하는 크롬 확장 프로그램이다.

서비스는 SWEA를 최우선으로 지원하고, 이후 프로그래머스, 정올, LeetCode 순서로 플랫폼을 확장한다. 사용자가 문 제를 제출하면 문제 정보, 제출 코드, 사용 언어, 제출 결과를 자동으로 기록하고, 풀이 과정과 오답 원인을 추가할 수 있 도록 한다.

각 문제에는 AI 활용 수준을 함께 기록한다. AI를 전혀 사용하지 않은 경우부터 개념 검색, 부분 힌트, 풀이 방향 도움, 코 드 일부 참고, 전체 풀이 참고, AI 풀이 학습까지 단계적으로 구분한다. 또한 AI 활용 목적, 기여 비율, 현재 이해도, AI 없 이 다시 풀 수 있는지를 기록하여 단순한 정답 수가 아니라 실제 학습 상태를 확인할 수 있도록 한다.

문제를 해결하는 과정에서 사용한 AI와 풀이 완료 후 실행한 AI 코드 리뷰는 별도로 관리한다. 이를 통해 사용자가 혼자 해결한 문제에 대해 사후 코드 품질 검토만 받은 경우도 정확하게 기록할 수 있다.

AI 도움을 많이 받은 문제는 복습 우선순위를 높이고, 기존 코드와 AI 답변을 숨긴 상태에서 다시 풀도록 지원한다. 복습 과정에서는 최초 풀이의 AI 활용 수준과 현재 활용 수준을 비교하여 사용자가 점차 독립적으로 문제를 해결할 수 있게 되었는지 확인한다.

사용자가 자신의 API Key를 등록하면 코드 리뷰, 복잡도 분석, 개선점 제안, 풀이 요약, 복습 질문 생성 등의 기능을 선 택적으로 사용할 수 있다.

완성된 기록은 풀이 언어에 맞는 소스 파일로 내보낼 수 있으며, 코드와 README를 함께 생성하여 GitHub에 업로드할 수 있다. Notion은 풀이 과정, AI 활용 기록, 오답 원인, 복습 내용을 관리하는 학습 노트로 활용한다.

서비스 출시 이전이나 사용 이전에 풀었던 문제도 직접 입력, 소스 파일, Markdown, JSON 등의 방식으로 추가할 수 있다. 신규 자동 기록과 기존 풀이 기록은 중복 검사를 거쳐 통합하며, 동일 문제의 여러 제출, 여러 언어 풀이, 여러 복습 기록을 하나의 문제 아래에서 관리한다.

초기 MVP는 SWEA와 프로그래머스 자동 수집, 기존 풀이 등록, AI 활용 수준 기록, 로컬 저장, 언어별 파일 내보내기, 사 용자 API Key 기반 AI 코드 리뷰, Notion 보조 연동, GitHub 수동 업로드에 집중한다.

본 서비스의 최종 목표는 정답 코드를 많이 저장하는 것이 아니다. 사용자가 어떤 방식으로 문제에 접근했고, 어디에서 막혔으며, AI를 어떤 범위에서 활용했고, 이후 AI의 도움 없이 문제를 다시 해결할 수 있게 되었는지를 지속적으로 기록 하는 통합 알고리즘 학습 환경을 제공하는 것이다.

## 부록 A. Git 커밋 및 코드 컨벤션 자동 검증 제안

본 부록은 CodeArchive의 GitHub 업로드 흐름에 커밋 메시지 규칙과 코드 품질 검사를 추가하여, 규칙을 지키지 않은 변경 사항이 커밋되거나 보호 브랜치에 병합되는 것을 방지하기 위한 제안이다. 기존 제안서의 GitHub 업로드 기능은 저장소·브랜치·경로 선택, 파일 미리보기, 커밋 메시지 확인, 업로 드 및 커밋 URL 저장 흐름을 갖고 있으므로, 커밋 직전 검증 단계와 원격 CI 검증 단계를 추가하는 방 식으로 확장한다.

### A.1 적용 목적

- 커밋 메시지 형식을 통일하여 기능 추가, 오류 수정, 문제 풀이, 복습 기록 등 변경 목적을 빠르게 파

악한다.

- TypeScript 확장 프로그램 소스의 포맷, 네이밍, 사용하지 않는 변수, 잠재 오류를 자동 검사한다.
- 내보내거나 GitHub에 업로드하는 Java 풀이 코드에도 선택적으로 코드 스타일 검사를 적용한다.
- 로컬 Git Hook을 우회하더라도 GitHub Actions와 보호 브랜치 설정에서 다시 검사한다.
- 검사 실패 원인과 수정 명령을 사용자에게 명확하게 안내하여 기록 자동화 흐름을 방해하지 않도록

한다.

### A.2 커밋 메시지 컨벤션

기본 형식은 다음과 같다. <type>(<scope>): <subject>

예시: feat(github): GitHub 업로드 미리보기 추가
