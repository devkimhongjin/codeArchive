# 커뮤니티 공유 계약

2026-08-31 사용자 결정: 커뮤니티 구현을 완료할 때까지 진행한다. 신규 기능 P1은 커뮤니티(#45), P2는 프로그래머스→정올(#141), P3는 분석·리더보드(#142)다. 이 결정은 기존 베타 우선순위 문서의 커뮤니티 유보를 이번 범위에 한해 변경한다. Extension 정리 #86의 미확인 E2E는 완료한 것으로 간주하지 않는다.

Root/integrator가 apps/api/**, apps/web/**, 이 문서의 API·DB·UI 계약을 통합한다. PR #145는 develop 기반이며 PR #144의 검색·정렬과 별도다. Extension, shared-types, 인증 권한, provider, 자동 배포는 변경하지 않는다.

## 공개와 성공 자격

- 모든 기존/신규 풀이 기본 PRIVATE. 공개는 사용자가 코드·정보를 확인하고 별도 체크박스에 동의한 후 요청한다. 자동 동기화 동의와 무관하다.
- PUBLIC은 무인증 인터넷 공개가 아니라 **같은 플랫폼 + 문제 ID의 성공 수집 풀이를 공개한 사용자끼리 공유**다.
- 서버는 매 목록/상세/링크/댓글 CRUD/좋아요/신고 요청에 대상 PUBLIC과 요청자의 동일 문제 ACCEPTED+accepted_capture+PUBLIC을 검사한다. 본인 풀이의 공유 설정만 소유자에게 별도로 제공한다.
- 플랫폼은 기존 수집 계약의 대문자 식별자, 문제 번호는 수집 시 trim된 **불투명 canonical ID를 정확히 비교**한다. 플랫폼 간 같은 번호를 섞지 않으며 숫자로 변환하거나 제목으로 매칭하지 않는다. 현재 지원 API 플랫폼은 SWEA뿐이다. 향후 플랫폼 수집기는 URL에서 정규 식별자를 추출해야 한다.
- `accepted_capture`는 검증된 bulk 수집 경로에서만 부여한다. 서버 결과·문제·언어·코드·observedAt이 수집 payload와 모두 일치해야 한다. 중복 재동기화는 출처만 확인하고 사용자 수정 내용을 덮어쓰거나 공개하지 않는다.
- 기존 기록은 수동 수정 여부를 알 수 없으므로 migration으로 출처를 추정하지 않는다. 성공 수집 원본 재동기화 또는 새 성공 제출을 수집하면 공유 가능하다. 이미 ACK된 기존 원본을 강제로 재전송하는 기능은 추가하지 않는다. 기존 사용자에게는 SWEA 성공 풀이 재수집→동기화를 안내한다.
- 일반 PUT으로 ACCEPTED를 쓰거나 source 표시를 바꾸는 것만으로 자격을 얻지 못한다. DB trigger가 코드·언어·플랫폼·문제·결과 변경 시 출처·공개를 해제한다. 제목 변경은 공개 글에 반영한다. AI 결과는 포함하지 않는다.
- 신뢰 한계: 브라우저에서 관찰한 성공 결과이지 플랫폼의 공식 서명/재채점 검증은 아니다. 악의적으로 수집 API 전체를 위조하는 클라이언트를 증명으로 방어하지 못한다. UI에서 공식 검증이라고 표시하지 않는다.

## API와 수명

모든 경로는 `/api/v1/community` 하위이며 기존 세션 인증/정확한 Dashboard Origin 검사를 사용한다. POST로 상태 변경, DELETE로 댓글 삭제. 응답은 기존 ApiResponse envelope이고 `Cache-Control: no-store, private`다.

| 경로 | 메서드 | 동작 |
| --- | --- | --- |
| `/sharing/{ownId}` | GET / POST | 본인 상태 `{publicSolution,canPublish,eligible}` / `{publicSolution:boolean}` 변경 |
| `/peers/{ownId}?language=&offset=0` | GET | 본인 문제로 범위 고정, 본인 제외, 언어 정확 일치, 최근 공개순·UUID 보조 정렬, 20개+hasMore |
| `/solutions/{id}` | GET | 자격을 확인한 코드·작성자·좋아요/댓글 개수·내 좋아요 상태 |
| `/solutions/{id}/comments?offset=0` | GET | 오래된순·UUID 보조 정렬, 50개+hasMore |
| `/solutions/{id}/comments` | POST | `{body:string}`, 공백 금지·2000자 이하 |
| `/solutions/{id}/comments/{commentId}` | POST / DELETE | 본인 댓글 수정 / 삭제 |
| `/solutions/{id}/like` | POST | `{liked:boolean}`, 멱등 등록/취소, 자기 좋아요 금지 |
| `/solutions/{id}/report` | POST | `{reason:SPAM|ABUSE|SENSITIVE}`, 본인 신고 멱등 갱신 |

offset은 0..10000. 목록은 코드가 없고 상세에만 코드가 있다. 공개 DTO는 GitHub 계정명·내부 작성자 ID·문제/제목/언어·공개시각만 포함한다. private clientRecordId, 수집 시각, 성능 메모, AI 내용, 세션 정보는 제외한다. 자격 없는 상세·댓글·목록·수정은 존재/비존재 구분 없이 동일 404다. 서버 오류를 빈 목록으로 해석하지 않는다.

자격 및 대상 solution 행은 트랜잭션 동안 SHARE 잠금으로 고정한다. 같은 사용자의 커뮤니티 동작은 transaction advisory lock으로 직렬화하여 공개 변경과 잠금 승격 교착을 방지한다. 비공개·삭제·수정 커밋 이후 시작한 요청은 새 상태를 검사한다. 이전에 허용된 요청으로 이미 전달된 코드는 회수할 수 없다.

마지막 자격 풀이가 비공개/삭제되면 읽기 자격을 잃는다. 다른 자격 풀이가 남으면 유지한다. 대상 비공개는 모든 타인 경로를 차단하고, 재공개 시 기존 댓글/좋아요는 유지한다. 원본 삭제는 댓글·좋아요·신고를 cascade 삭제한다. 로컬 Extension 원본은 건드리지 않는다.

Web은 메모리에만 내용을 보관한다. 같은 창/브라우저 탭의 공개 철회·원본 수정/삭제는 무내용 invalidation 신호로 열린 공유 내용을 제거하고 재검사한다. 계정/문제 변경과 로그아웃에는 unmount·AbortSignal·generation 검사를 적용한다. 숨겨진 탭은 내용을 지우고 다시 보일 때 검사한다. 다른 기기에서 한 변경은 **최대 15초 간격 재검사** 또는 다음 조작/포커스로 반영한다. WebSocket/push가 없으므로 다른 기기의 이미 열린 화면을 0초에 지운다고 주장하지 않는다. 서버의 다음 요청 차단과 이미 전달된 바이트의 회수는 구분한다.

## 운영·남용 대응

- DB의 사용자별 분 단위 window: 공개 변경 30회, 댓글 작성/수정 30회, 좋아요 변경 60회, 신고 5회. 초과 429, 자동 재시도하지 않는다. 소규모 베타용 제한이며 대규모 DoS 방어를 대체하지 않는다.
- 댓글/코드는 React text node로 표시하고 HTML/Markdown 실행을 하지 않는다. 비밀키·개인정보를 붙이지 말라는 안내와 댓글 삭제 확인을 제공한다.
- 신고 내용은 사유 코드만 저장한다. 작성자는 PUBLIC에서만 신고하고, 운영자에게 자동 메시지/메일을 보내지 않는다. 운영자는 베타 운영 점검 때 DB의 `community_reports`를 확인해야 한다. 자동 삭제나 즉시 검토를 보장하지 않는다.
- 운영자는 report의 solution_id와 신고 사유만 우선 조회한다. 공개 코드나 사용자 토큰을 로그·GitHub 이슈에 붙여 넣지 않는다. 침해/비밀정보 신고는 당사자 확인 후 해당 solution의 community_public=false, published_at=NULL로 차단한다. 필요한 실제 운영 DB 조작은 소유자 승인 뒤 별도 수행한다. 일반 사용자에게 관리 API를 노출하지 않는다.
- 비공개 전환/삭제는 이미 복사된 코드의 외부 사본을 지우지 못한다. 공유 전 민감정보 확인이 필요하다.

## 검증 / 배포 경계

PostgreSQL Testcontainers 통합 테스트: default-private, 수집 출처, 수동/수정 차단, 동일/다른 문제·플랫폼, 무인증/소유권, 공개 철회/삭제, 중복 자격 유지, 댓글 CRUD/길이, 동시 좋아요, CSRF, 페이지 범위, 제한, cascade.

Web: 명시적 동의·미자격 버튼·HTML 안전 출력·CRUD·좋아요·신고·실패/재시도·로그아웃/늦은 응답·공유 링크. CI 타입 검사/전체 테스트/빌드 산출물을 로컬 합성 fixture 브라우저로 검증한다. 실제 배포 서버의 두 계정 E2E는 별도이며 과거 동기화 성공 보고로 대체하지 않는다.

비파괴 additive Flyway V7 파일을 작성하지만 실제 DB에 실행하지 않는다. 병합·V7 적용·API/Web 배포 후 같은 버전으로 확인해야 제품에서 사용할 수 있다. Extension 바이너리 변경은 없다.
