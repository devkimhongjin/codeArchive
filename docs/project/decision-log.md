# 결정 로그

작은 운영 결정과 범위 변경을 시간순으로 기록한다. 장기적·구조적 영향이 있는 결정은 `docs/adr`에 ADR을 작성하고 여기에는 링크만 남긴다.

## 기록 대상

- 승인된 요구사항, 일정, 우선순위 변경
- KPI 정의·목표·측정 방식 변경
- 검증 예외와 만료 시점
- 기능 플래그, 릴리스, 롤백 결정
- 기술 스택 후보의 채택 또는 거부

단순 구현 세부사항, 회의록 전문, 확정되지 않은 아이디어는 기록하지 않는다.

## 상태와 식별자

- 결정 ID: `DEC-YYYY-NNN`
- 상태: `proposed | accepted | superseded | rejected | expired`
- ADR ID: `ADR-NNNN`

### DEC-2026-001: 핵심 데이터 계약 채택

- 날짜: 2026-07-25
- 상태: accepted
- 요청자: TASK-0001 기획
- 승인자: 사용자 지시
- 관련 작업/KPI/ADR: TASK-0001, ADR-0001, 중복 감지율 KPI

#### 맥락

자동 수집, 기존 풀이 등록과 복습 기록이 같은 데이터를 안전하게 참조하려면 Problem,
SolutionSession, Submission, AIUsageRecord의 공통 계약이 선행되어야 했다.

#### 결정

- 엔터티 ID는 고정 namespace를 가진 UUID v4로 생성한다.
- 이벤트 시간은 UTC RFC 3339 밀리초, 달력 날짜는 `YYYY-MM-DD`로 저장한다.
- 외부 입력과 저장 경계는 추가 패키지 없는 순수 TypeScript 런타임 파서로 검증한다.
- Problem 1:N Session, Session 1:N Submission, Session 1:1 AIUsage 관계를 적용한다.
- 자연키는 strong/weak 중복 후보에 사용하며 자동 병합하지 않는다.

#### 근거와 검토한 대안

자연키 ID, namespace 없는 UUID, 시간 기반 ID, 외부 스키마 라이브러리와 AI 기록 내장
방식을 검토했다. 결정과 영향은 ADR-0001에 보존한다. 최종 재검증은 13개 테스트와 표준
품질 게이트 PASS를 확인했다.

#### 영향

- 일정: 일정이나 출시일 변경 없음
- 범위: TASK-0001의 타입·파서·정규화·관계 검증에 한정
- 구현: TASK-0002~0004가 재사용할 공통 데이터 경계 확정
- 검증: unknown field, 시간, 관계, 중복과 round trip 회귀 시험 필요
- 기록: 데이터 모델과 ADR 색인 갱신

#### 만료·재검토 조건

schemaVersion 2, 실제 migration, 자동 병합, 새 플랫폼 enum 또는 런타임 검증 라이브러리를
도입할 때 재검토한다.

### DEC-2026-002: 플랫폼 어댑터와 합성 fixture 계약 채택

- 날짜: 2026-07-26
- 상태: accepted
- 요청자: TASK-0002 기획
- 승인자: 사용자 지시
- 관련 작업/KPI/ADR: TASK-0002, ADR-0002, KPI-PROD-001

#### 맥락

플랫폼 DOM 변경이 공통 수집 경계로 전파되지 않게 하고, 실제 사이트 HTML·사용자 데이터
복사 없이 실패와 fallback을 재현할 계약이 필요했다.

#### 결정

- DOM 쿼리와 제출 관찰은 `src/platforms/**`에 격리한다.
- resolver는 URL만으로 어댑터를 선택하고 미지원 URL에서는 DOM을 읽지 않는다.
- 문제, 풀이와 제출 결과는 독립적으로 캡처하며 예상 가능한 실패는 구조화된 결과로
  반환한다.
- 필수값·코드·언어·DOM 계약 실패에서는 자동 저장을 중단하고 수동 등록 신호를 반환한다.
- 실제 DOM 복사본 대신 정상·선택 필드 누락·코드 누락·DOM 변경의 최소 합성·비식별
  fixture와 비지원 URL 메타데이터를 사용한다.

#### 근거와 검토한 대안

실제 DOM 전체 fixture, 공통 content script의 직접 selector 처리, 예외·빈 DTO 반환,
브라우저 E2E 단독 전략을 검토했다. 보안과 결정적 회귀 테스트, 실패 안전성을 위해 현재
계약을 선택했다. 상세한 장단점과 롤백은 ADR-0002에 보존한다.

#### 영향

- 일정: 출시일 변경 없음. 실제 SWEA 호환성 검증은 M2로 유지
- 범위: TASK-0002 공통 계약, resolver, SWEA 최소 어댑터와 합성 fixture에 한정
- 구현: 새 플랫폼은 독립 어댑터와 registry 등록으로 확장
- 검증: 합성 fixture 4종, focused 11개와 전체 24개 테스트 PASS
- 기록: 어댑터 규격, 아키텍처, 보안 정책과 ADR 색인 갱신

KPI-PROD-001과 실제 언어·제출 감지율은 실제 표본이 없어 `Not measured`다. Chrome
unpacked extension smoke도 `Not Run`이며 통합 전 수동 확인이 필요하다.

#### 만료·재검토 조건

실제 SWEA selector·host permission, 실제 DOM fixture, 네트워크 E2E, 새 플랫폼이 요구하는
공통 계약 변경 또는 warning별 자동 저장 정책을 도입할 때 재검토한다.

## 기록 원칙

1. 사실, 가정, 결정을 구분한다.
2. 사후에 내용을 지우지 않고 상태를 `superseded`로 바꾸고 후속 결정을 연결한다.
3. 검증 예외는 이유, 소유자, 만료일, 보완 통제를 포함한다.
4. 테스트 0개나 실행하지 않은 게이트를 허용하는 영구 예외는 만들지 않는다.
5. 결정으로 변경된 문서와 인수 조건을 함께 갱신한다.
