# KPI 정의와 측정 계약

## 원칙

- 모든 KPI는 고유 ID, 목적, 계산식, 데이터 원천, 기간, 소유 역할을 가진다.
- 원시값과 계산값을 함께 보존한다. 표본 수가 없거나 측정하지 않은 값은 `N/A`로 기록하며 0으로 대체하지 않는다.
- 기준선이 없는 KPI는 먼저 2회 이상 측정한 뒤 목표를 승인한다.
- 성공률의 분모에서 실패·중단·미지원 사례를 임의로 제외하지 않는다.
- KPI 목표 변경은 기획 승인과 `docs/project/decision-log.md` 기록이 필요하다.
- 제품 KPI와 개발 품질 KPI를 혼합해 해석하지 않는다.

## 측정 세부 규칙

### 품질 게이트

`KPI-QUAL-001`의 한 건은 같은 커밋 SHA에서 lint, format check, typecheck, test, build, artifact 검사를 모두 실행한 경우에만 분모에 포함한다. `BLOCKED`는 별도 집계하며 PASS로 계산하지 않는다.

### 커버리지

커버리지는 생성 파일, fixture, 타입 선언을 제외할 수 있지만 제외 목록은 설정 파일로 고정한다. 임계치를 낮추려면 근거와 만료 시점이 있는 ADR이 필요하다.

### False-green

다음 중 하나면 `KPI-QUAL-003` 한 건으로 기록한다.

- 테스트가 0개인데 성공 처리됨
- `--passWithNoTests`, `|| true` 등으로 실패가 숨겨짐
- 실행하지 않은 검증을 PASS로 표시함
- 현재 커밋이 아닌 과거 빌드 아티팩트를 검증함
- skip/only 때문에 필수 시나리오가 실행되지 않음

### 제품 이벤트

개인정보와 풀이 코드는 KPI 원시 데이터에 포함하지 않는다. 외부 전송은 명시적 동의와 보존 정책이 준비되기 전에는 사용하지 않으며, 그전에는 fixture 또는 사용자가 내보낸 익명 집계만 사용한다.
