# 보안 정책

## 비밀 정보

- API Key, OAuth 토큰, GitHub 토큰은 저장소에 커밋하지 않는다.
- 로컬 설정은 `.env.local`에 저장하고 `.env.example`에는 키 이름만 문서화한다.
- 토큰과 개인정보를 콘솔 로그, 오류 메시지, 분석 이벤트에 포함하지 않는다.
- 사용자가 제공한 비밀 정보는 가능한 경우 `chrome.storage.local`에 저장하고 외부 전송 전에 명시적으로 알린다.

## 확장 프로그램 권한

- `manifest.json`에는 실제 기능에 필요한 최소 권한만 선언한다.
- 새로운 host permission이나 외부 API 연동을 추가할 때 수집 데이터와 전송 대상을 문서화한다.
- 자동 업로드는 기본적으로 비활성화하고 사용자 확인 후 실행한다.

## 플랫폼 어댑터와 오류

- 플랫폼 DOM 접근은 `src/platforms/**`에만 둔다.
- 어댑터 오류와 warning에는 실패 코드, 단계, 복구 가능 여부, fallback과 허용된 필드명만
  기록한다.
- 오류, 로그와 분석 이벤트에는 DOM 원문, selector 전체, 문제 본문, 공식 해설, 코드 원문,
  사용자명, 이메일, 쿠키, 세션·제출 식별자와 토큰을 넣지 않는다.
- 알 수 없는 값은 임의의 정상 값으로 추정하지 않는다. 필수값·코드·언어 실패 시 자동
  저장을 중단하고 수동 등록 신호를 반환한다.
- 제출 결과를 판별할 수 없으면 `accepted`로 추정하지 않고 `unknown`과 warning으로
  전달한다.

## 테스트 fixture

- 실제 사이트 HTML 캡처본 대신 테스트에 필요한 요소만 손으로 작성한 최소 합성 HTML을
  사용한다.
- fixture와 메타데이터에 합성 여부, 목적, 기대 결과와 갱신 이유를 기록한다.
- 실제 문제 본문, 공식 해설, 전체 테스트 케이스, 실제 사용자 코드, 개인정보, 쿠키, 세션
  값과 비밀 정보를 fixture에 넣지 않는다.
- `<script>`, 외부 리소스, 네트워크 요청과 실행 가능한 추적 코드를 넣지 않는다.
- selector 계약이 의도적으로 바뀔 때만 fixture를 최소 범위로 갱신한다.
- 실제 DOM이 필요한 조사는 사용자의 별도 승인, 플랫폼 정책·저작권·개인정보 검토와
  비식별 절차가 승인되기 전까지 수행하지 않는다.

TASK-0002의 SWEA fixture 4종은 합성·비식별 검토와 민감 패턴·외부 리소스 정적 검색을
통과했다. 이 결과는 실제 SWEA DOM이나 로그인 세션을 조사했다는 의미가 아니다. 새 권한,
host permission, 외부 통신, 저장과 마이그레이션 변경은 없었다.

## 취약점 제보

공개 이슈에 토큰, 개인정보, 재현용 비밀 값을 올리지 않는다. 저장소 관리자가 제공하는 비공개 채널로 재현 절차와 영향 범위를 전달한다.
