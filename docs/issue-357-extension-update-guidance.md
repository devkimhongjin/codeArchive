# 확장 릴리스 자동 확인 및 업데이트 안내 — #357

- 팝업을 열거나 Chrome을 시작/설치할 때 최신 릴리스를 확인한다. Chrome alarms의 하루 주기 확인도 유지한다. worker 재시작은 기존 alarm 일정을 다시 시작하지 않는다.
- 성공한 확인은 하루 동안 재사용하고, 실패는 5분 후 다시 확인한다. 직접 다시 확인도 최소 1분 간격이며 동시 요청은 하나로 합친다. 요청 제한 시간은 5초다.
- CodeArchive의 고정 GitHub 저장소 public releases API만 사용한다. 쿠키·인증 헤더·사용자 풀이를 전송하지 않는다. 추가 host permission은 `https://api.github.com/*`다.
- 태그, 고정 확장 ID, metadata, asset 주소, ZIP digest를 검증한 후보 중 버전이 가장 높은 릴리스를 사용한다. 새 릴리스가 더 높은 대시보드 버전을 요구해도 확장의 업데이트 안내에는 표시할 수 있다.
- 네트워크 실패를 최신 버전 확인 성공으로 표시하지 않는다. 이전에 검증한 안내가 있으면 이전 확인 결과임을 표시하고 링크를 유지한다. 저장된 링크도 사용 전에 다시 검증한다.
- 릴리스 확인과 팝업 로컬 표시가 독립적으로 진행된다. ZIP 다운로드·실행, 설치 폴더 수정, 확장 자동 reload는 하지 않는다.
- Windows 압축 해제 확장은 새 ZIP을 기존 설치 폴더에 교체하고 확장 관리에서 새로고침하는 방법을 안내한다. 더 넓은 Windows helper 자동 교체 범위는 #320에 남는다.
- 0.2.2는 일괄 동기화/커밋 API와 함께 배포한다. 기존 설치 경로로 빌드 파일을 복사하는 설정은 유지한다.

## 검증

자동 테스트는 중복 확인 요청/캐시/timeout, 오래된 버전, 잘못된 repo·digest·ID·draft, 캐시 링크 검증, 느린 릴리스 응답과 로컬 표시의 독립성을 확인한다.

Chrome 화면 검증은 `node test/history-browser-fixture.mjs` 실행 후
`http://127.0.0.1:5178/__fixture/popup`에서 실제 popup HTML/CSS/View를 사용한다.
릴리스 응답만 합성 데이터이며 확장 파일 설치 및 실제 updater 네트워크 실행 결과를 대신하지 않는다.
