# 확장 통합 검증

## 사용 구조

팝업의 **대시보드 열기**는 확장 패키지에 포함된 `dashboard.html`을 Chrome 탭에서 엽니다. 전체 풀이, 설정, 커뮤니티, 과거 풀이 동기화·GitHub 커밋, GitHub 관리 화면을 함께 제공합니다. 과거 풀이 수집은 기존 `history.html`을 사용합니다.

PC 앱을 실행하거나 연결 코드를 입력하지 않아도 됩니다. 기존 고정 확장 ID와 Chrome 프로필의 IndexedDB 저장소를 사용합니다. PC 앱과 서버의 기존 기록은 삭제하지 않습니다.

신규 정답 제출은 로그인한 계정으로 항상 자동 동기화합니다. 팝업에는 로컬 보관·자동 다운로드·과거 수집 바로가기를 표시하지 않으며, 최근 목록은 동기화된 문제별로 표시합니다. 과거 수집은 관리 화면에서 시작하며, 미전송 데이터는 재시도를 위한 내부 저장소에 유지합니다. 새 제출의 자동 전송은 수집 시 연결한 계정에 묶이며 계정이 바뀌어도 다른 계정의 대기 코드를 자동 업로드하지 않습니다. 기존 버전의 계정 식별 정보가 없는 대기 기록과 과거 수집은 대시보드에서 명시적으로 동기화합니다. 서버 기능은 기존 API를 사용하며, 새 웹 탭에서 GitHub 로그인한 후 확장 관리 화면으로 돌아옵니다. 인증 쿠키는 Chrome이 관리하며 확장 코드가 쿠키 값을 읽지 않습니다. CSRF와 계정 확인을 유지합니다.

Chrome이 완전히 종료되면 확장 작업은 진행되지 않습니다. 과거 수집 중에는 수집 화면과 원본 사이트 창을 함께 열어 두세요. 이미 저장한 항목과 기존 수집 상태를 보존하며, 중단 후 원본 사이트 상태를 확인하고 다시 실행합니다. 진행 중인 수동 업로드·커밋은 완료 여부를 서버에서 확인한 뒤 다시 요청하세요.

## 로컬 검증 폴더

로그인 복귀는 확장 관리 화면이 만든 일회성 nonce와 Chrome session 저장소의 로그인 탭/대상 탭/만료 정보를 사용합니다. 로그인 탭은 `about:blank`로 먼저 만들고 복귀 정보를 저장한 뒤 OAuth 주소로 이동합니다. 승인된 웹 origin의 루트로 돌아오면 원래 관리 문서의 메모리 nonce 응답을 확인한 뒤 그 탭과 창을 활성화하고 로그인 탭만 닫습니다. `tabs`·`cookies` 권한을 추가하지 않으며 `Tab.url`이 없어도 문서 응답으로 검증합니다. 원래 문서가 닫히거나 새로고침·이동하거나 다른 로그인 시도로 바뀌었거나 10분이 지나면 자동 복귀하지 않습니다. 일반 웹 대시보드 로그인과 서버 OAuth 세션 방식은 변경하지 않습니다.

`apps/extension/build.local.json`의 `installedExtensionDir`에 현재 Chrome에 등록한 폴더를 지정하고 `npm --prefix apps/extension run build`를 실행합니다. 빌드는 기존 파일을 백업한 뒤 해당 폴더를 갱신합니다. Chrome에서 CodeArchive 확장 새로고침(↻) 후 팝업을 엽니다. 설정 파일은 Git에 포함하지 않습니다.

대시보드 번들은 `apps/dashboard/dist-extension`에서 상대 경로로 생성되어 확장 `dist/dashboard.html` 및 `dist/assets`에 포함됩니다. 빌드 전에 dashboard와 extension의 `npm ci`를 실행합니다. Shiki는 확장 CSP를 유지하기 위해 JavaScript 정규식 엔진을 사용합니다. 원격 스크립트·eval·추가 쿠키 권한을 사용하지 않습니다.

GitHub 저장소가 연결돼 있으면 팝업의 자동 커밋 스위치로 바로 ON/OFF합니다. 서버의 현재 계정과 설정 버전을 확인해 저장하며, 자동 동기화 연결도 새 설정 버전에 맞춰 갱신합니다. 저장 중에는 중복 클릭을 막고, 실패하거나 결과가 불확실하면 확인 안내를 표시합니다. 저장소가 없으면 GitHub 관리 탭을 열어 연결합니다. 연결·동기화 복구가 필요한 경우에는 대시보드에서 최신 상태를 확인하세요.

## 검증 순서

1. PC 앱 없이 팝업이 열리고 대시보드 버튼이 확장 탭을 여는지 확인합니다.
2. 전체 풀이에서 기존 로컬 기록·검색·20개 페이지·코드·복사·다운로드·65개 테마를 확인합니다.
3. 연동 가이드의 확장 버전·로컬 저장소 연결 상태를 확인합니다.
4. GitHub 로그인한 뒤 관리 탭으로 돌아오고 기존 서버 풀이·설정을 읽는지 확인합니다. 계정 교체·로그아웃 시 이전 계정 코드가 남지 않아야 합니다.
5. 승인된 테스트 풀이만 수동 동기화하고 GitHub 커밋·커뮤니티 정렬·좋아요·댓글·중복 공개 설정을 확인합니다. 검증을 이유로 운영 기록을 임의 변경하지 않습니다.
6. 과거 수집 화면 이동·다시 열기·작업 중단 후 완료 항목 보존을 확인합니다.
7. 연결된 저장소의 팝업 ON/OFF와 재열기 후 유지, 자동 동기화 연결 유지, 미연결 시 GitHub 관리 탭 이동을 확인합니다.

## 배포

설치 EXE 작업은 사용자 요청으로 중지했습니다. 검증 완료 후 Chrome 웹스토어 등록을 준비합니다. [웹스토어 준비](extension-webstore.md)의 명령으로 localhost 권한과 소스맵을 제외한 ZIP·체크섬·검사 보고서를 생성합니다. 등록에는 개발자 계정, 개인정보 안내, 권한 설명 및 실제 검증이 필요합니다. 웹스토어에서 발급되는 실제 확장 ID를 확인한 뒤 API 허용 origin과 공개 릴리스 ID를 맞춰야 하며 추측한 ID로 설정하지 않습니다. 공개 버전은 기존 master 기준 릴리스 규칙과 develop 선행 병합을 따릅니다. Netlify 배포는 하지 않습니다.
