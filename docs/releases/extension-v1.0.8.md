# CodeArchive Extension v1.0.8

## 변경 사항

### 정답 제출이 임시 저장에 머물던 문제 (#497)
- 대시보드에서 연결한 뒤 제출한 정답이 임시 저장에 머물고, 대시보드를 열어 둔 채 `지금 동기화`를 눌러도 `연결 정보를 확인하지 못했어요. 대시보드를 열면 연결이 갱신돼요.`만 나오던 문제를 고쳤습니다.
  - 서버가 주는 전송 주소는 상대 경로인데, 임시 저장을 보내기 전의 연결 확인이 절대 주소만 받았습니다. 대시보드는 같은 연결 정보를 재사용하므로 다시 열어도 풀리지 않았습니다.
  - 1.0.3부터 있던 문제이고, 사이트나 언어와 관계없습니다.
- 임시 저장에 머물러 있던 제출은 지워지지 않았으므로, 업데이트 뒤 연결이 확인되면 전송됩니다.

### 오래 쓰지 않은 뒤 연결이 끊겨 보이던 문제 (#498)
- **팝업:** 서버가 잠들어 있으면 첫 응답에 20초 안팎이 걸리는데, 팝업은 8초 만에 포기하고 `서버 연결 확인 필요`를 보여 줬습니다. 이제 28초까지 기다리고, 그 안에서는 연결이 끊기거나 서버 오류가 와도 다시 읽습니다. 3초가 지나면 `서버 깨우는 중`을 보여 줍니다.
- **로그인 유지 (서버):** 로그인 쿠키가 로그인한 날부터 30일 뒤에 만료되어, 매일 써도 다시 로그인해야 했습니다. 이제 쓸 때마다 30일이 새로 시작됩니다.

### SWEA 과거 풀이 후보 찾기 (#496)
- 읽지 못한 문제 하나 때문에 후보 찾기 전체가 멈추던 문제를 고쳤습니다. 그 문제만 빼고 끝까지 진행하며, 빠진 문제를 화면에 알립니다.
  - 목록에서 형식을 읽지 못한 카드: `목록에서 형식을 읽지 못한 문제 2건(#45, Problem 47)은 이번 후보에서 빠졌습니다.`
  - 제출 이력을 읽지 못한 문제: `제출 이력을 읽지 못한 문제 N건(#…)은 이번 후보에서 빠졌습니다.`
- 제출 이력을 3문제 연달아 읽지 못하면 사이트 문제로 보고 멈춥니다. 페이지의 카드 수가 맞지 않을 때와 본인이 아닌 제출이 보일 때도 지금처럼 멈춥니다.
- SWEA 요청에 시간 제한을 두었습니다. 20초 동안 응답이 없으면 끊고 한 번 다시 보냅니다. 이전에는 끝없이 기다릴 수 있었습니다.

## 업데이트 안내

- 이번 버전은 권한을 바꾸지 않습니다. `manifest.json`의 권한과 접속 허용 사이트는 1.0.7과 같습니다. 기존 로그인, GitHub 연결, 자동 커밋 설정은 그대로 유지됩니다.
- 서버 변경(#498 로그인 쿠키)은 2026-11-02에 배포했습니다. 이전 확장 버전과도 함께 동작하며, DB 변경은 없습니다.
- 지금 로그인 쿠키가 살아 있으면 다음 사용 때 연장됩니다. 이미 만료됐다면 한 번은 다시 로그인해야 합니다.
- 확장 갱신 전에 열려 있던 문제 탭에는 새로고침 안내가 표시될 수 있습니다. 작성 중인 코드를 확인한 뒤 새로고침해 주세요.

## 알려진 한계

- 서버가 잠들어 있으면 팝업이 깨울 때까지 기다리는 것일 뿐, 대기 자체가 없어지지는 않습니다.
- 스토어 설치본의 실제 확인은 [#456](https://github.com/devkimhongjin/codeArchive/issues/456)에서 이어갑니다.
  - #497: 개발용 빌드에서 임시 저장 뒤 전송을 확인했습니다.
  - #496: 다른 사용자 계정에서 멈춘 실제 원인 카드는 아직 확인하지 못했습니다. 이 버전부터 화면에 빠진 문제가 표시됩니다.
  - #498: 팝업 대기와 쿠키 저장은 자동 테스트로 확인했습니다.
- 1.0.7의 한계가 그대로 남아 있습니다. 실시간 수집된 SQL 풀이가 과거 풀이 후보에서 빠지는지 확인하지 못했고, Oracle SQL은 가져오지 않습니다. 이미 서버에 두 번 등록된 SWEA 풀이는 정리되지 않고, 정올은 후보 목록에 제출 시각이 없어 실시간 수집분과 맞춰 볼 수 없습니다.

## 배포 절차

- 이번 버전부터 `DEFAULT_PUBLISH`로 심사를 제출합니다(#499). 심사를 통과하면 Developer Dashboard 조작 없이 바로 공개됩니다.
- 2026-11-02 상태 조회 기준 스토어에는 1.0.7이 공개돼 있고 심사 중이거나 대기 중인 제출은 없습니다.
- 심사 제출, 실제 스토어 공개, 설치본 업데이트 확인은 서로 구분해서 기록합니다.
