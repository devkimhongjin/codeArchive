# CodeArchive Extension v1.0.6

## 변경 사항

### 제출현황에서 바로 동기화·커밋 (#480)
- 자동 수집이 실패했을 때 정올·프로그래머스·SWEA의 내 제출현황에서 바로 `동기화`(서버 등록)와 `커밋`(GitHub)을 누를 수 있습니다.
  - 정올: 내 제출현황의 정답 행, 프로그래머스: 문제의 `제출 내역` 100점 행, SWEA: 제출현황의 문제 카드.
  - `동기화`는 서버에 없는 정답 제출일 때만, `커밋`은 서버에 등록됐고 커밋 전이거나 실패했으며 GitHub 저장소가 연결돼 있을 때만 켜집니다.
  - 서버에 이미 있는 제출은 다시 만들지 않습니다. 같은 사이트 제출 번호, 또는 제출 번호가 없는 실시간 수집분은 문제·언어가 같고 제출 시각이 2분 이내인 것으로 맞춰 봅니다. 여러 개가 겹치면 `확인 필요`로 막습니다.
- 정올 제출현황으로 사이트 안에서 이동해 들어올 때 `처리하지 못했습니다`가 보이고 새로고침해야 버튼이 나오던 문제를 고쳤습니다. (#488)

### 수집 안정성
- 서버가 거부한 임시 저장 풀이 하나가 대기열 맨 앞에서 뒤의 풀이 전송을 영원히 막던 문제를 고쳤습니다. 거부된 풀이는 건너뛰고 다음 풀이를 계속 보내며, 아무 풀이도 지우지 않습니다. 팝업에 `지금 동기화` 버튼이 생겼고, 거부 사유와 함께 결과를 보여 줍니다. (#481)
- 정올 C++ 제출이 수집되지 않던 문제를 고쳤습니다. 화면의 `C++20`과 채점 요청의 `CPP20`을 비교하다 `++`가 지워져 달라졌고, Java·Python·Kotlin은 우연히 일치해 드러나지 않았습니다. (#482)

### 과거 풀이 수집
- SWEA·프로그래머스도 제출 목록을 백그라운드 탭에서 열어 수집합니다. 프로그래머스의 문제 상세 탭도 활성 탭이 아니라 같은 창의 비활성 탭으로 열려 탭이 계속 앞으로 튀어나오지 않습니다. 로그인하지 않았으면 로그인 페이지로 이동하는 즉시 알고 안내합니다. (#484)
- 프로그래머스 후보 찾기가 읽지 못한 문제 하나 때문에 통째로 중단되던 문제를 고쳤습니다. 한 번 더 시도한 뒤 그 문제를 후보에서 빼고 계속하며, 빠진 문제 번호를 화면에 알립니다. (#484)
- 실시간 수집으로 이미 서버에 있는 풀이가 과거 풀이로 다시 등록되던 문제를 고쳤습니다(프로그래머스 22건 중 7건, SWEA 9건 확인). 서버 풀이와 문제·언어·2분 이내 제출 시각으로 맞춰 후보에서 제외합니다. (#484, #487)
- 정올은 탭이 백그라운드에 있으면 사이트가 응답하지 않아 수집이 멈추므로, 후보 찾기·가져오기를 시작할 때 이 화면 옆(오른쪽 절반)에 정올 제출현황 창을 따로 열어 앞으로 가져옵니다. 이 화면의 탭은 그대로 남고, 끝나면 창이 닫힙니다. 창이 다른 창에 가려지거나 최소화되어 15초 동안 진행이 없으면 창만 다시 앞으로 올립니다. 수집이 끝날 때까지 그 창을 가리거나 최소화하지 마세요. 창을 만들 수 없으면 앞으로 띄운 탭으로 대신합니다. (#487, #488)
- SWEA·프로그래머스도 숨은 탭이 15초 동안 진행하지 못하면 그 탭을 한 번 앞으로 가져옵니다. (#487)
- 정올 창이 열리자마자 닫히던 문제를 보강했습니다. 홈 화면에 계정 링크가 여러 개 보여도 본인에게만 보이는 `정보 수정` 탭이 있는 계정을 찾아 열고, 프로필 화면에서 계정 이름을 읽지 못해 본인 확인에 실패하던 경우 화면 제목과 제출자 표시로도 읽습니다. 그래도 실패하면 어느 항목을 찾지 못했는지 화면에 표시합니다. (#488)

### 대시보드·팝업
- 과거 풀이 화면에 정올·SWEA·프로그래머스 로그인 상태 카드를 추가했습니다. `로그인됨 · 닉네임` / `로그인 필요` / `확인하지 못함`을 보여 주고, 로그인이 필요하면 해당 사이트 로그인 페이지를 새 탭으로 엽니다. 비밀번호는 입력·전달·저장하지 않습니다. (#485)
- 전체 풀이 정렬을 `최근 저장순`(기본값), `최근 풀이순`, `오래된 풀이순`으로 나눴습니다. 기존 `최신 저장순`은 실제로는 사이트 풀이 시각 기준이라, 가져온 과거 풀이가 목록 중간에 놓여 추가되지 않은 것처럼 보였습니다. 일괄 GitHub 커밋은 수집 화면 아래로 옮겼습니다. (#485)
- 팝업 최근 풀이의 `동기화됨`을 누르면 대시보드에서 그 풀이가 열리고, `GitHub 완료`를 누르면 커밋된 GitHub 파일 페이지가 열립니다. 서버가 링크를 주지 않는 이전 서버에서는 지금처럼 일반 라벨로 표시됩니다. (#486)
- 일괄 GitHub 커밋의 팝업 진행률이 몇 초 간격으로 갱신됩니다. 전부 접수한 뒤 서버 상태를 한 번만 확인해 다음 갱신이 30초 알람까지 밀리던 문제를 고쳤습니다. (#488)

### GitHub 커밋 작성자 (#483, 서버)
- 서버가 만드는 커밋의 작성자가 `codearchive[bot]`이 아니라 저장소 주인 계정으로 기록되어 GitHub 기여 그래프에 반영됩니다. 서버 배포 이후에 만든 커밋부터 적용되며, 이미 봇 이름으로 올라간 커밋은 바뀌지 않습니다. 커밋이 저장소의 기본 브랜치에 있어야 하고, 포크 저장소가 아니어야 하며, 비공개 저장소는 GitHub 프로필에서 `Private contributions` 표시를 켜야 다른 사람에게 보입니다.

## 업데이트 안내

- 이번 버전은 권한을 바꾸지 않습니다. `manifest.json`의 권한과 접속 허용 사이트는 1.0.5와 같습니다. 기존 로그인, GitHub 연결, 자동 커밋 설정은 그대로 유지됩니다.
- 서버 변경(#483, #486, DB 마이그레이션 V31 `github_commit_jobs.github_url` 추가)은 2026-10-27에 스테이징에 배포했습니다. 이전 확장도 새 서버와 함께 동작합니다(응답 필드 추가만). 팝업 링크는 서버가 링크를 줄 때만 나타납니다.
- 정올 수집은 별도 창으로 열립니다. 팝업 차단 설정이나 창 크기에 따라 배치가 달라질 수 있습니다.
- 확장 갱신 전에 열려 있던 문제 탭에는 새로고침 안내가 표시될 수 있습니다. 작성 중인 코드를 확인한 뒤 새로고침해 주세요.

## 알려진 한계

- 이미 서버에 두 번 등록된 SWEA 풀이(같은 시각·같은 코드)는 이 버전으로 정리되지 않습니다. 서버에 풀이를 삭제하는 기능이 없습니다. 일괄 GitHub 커밋 대상에서 제외해 주세요.
- 정올은 후보 목록에 제출 시각이 없어 실시간 수집분과 맞춰 볼 수 없습니다. 정올 풀이가 이중으로 등록될 가능성은 별도로 확인합니다.
- 정올 새 창, 본인 확인 보강, 일괄 커밋 진행률은 개발용 빌드의 자동 테스트로 확인했고, 스토어 설치본의 실제 계정 확인은 [#456](https://github.com/devkimhongjin/codeArchive/issues/456)에서 이어갑니다.

## 배포 절차

- `STAGED_PUBLISH`로 심사를 제출합니다. 심사를 통과해도 자동 공개되지 않고, Developer Dashboard에서 게시해야 공개됩니다. 심사 완료 후 30일 안에 게시해야 합니다.
- 2026-10-27 상태 조회 기준 스토어에는 1.0.5가 공개돼 있고 심사 중이거나 대기 중인 제출은 없습니다.
- 심사 제출, 실제 스토어 공개, 설치본 업데이트 확인은 서로 구분해서 기록합니다.
