# CodeArchive Extension v1.0.3

## 변경 사항

- 업데이트·재활성화·Chrome 시작 뒤 기존 서버 로그인 쿠키로 계정과 자동 동기화 연결을 다시 확인합니다. 유효한 연결은 재사용하고, 만료된 연결은 동일한 로그인 계정에서만 복원합니다.
- 일시적인 서버 연결 오류로 저장된 연결을 지우거나 서버의 연결 권한을 철회하지 않도록 수정했습니다.
- 문제 제출 시 기기에 저장된 자동 동기화 계정과 권한을 확인합니다. 정답으로 확인한 풀이는 먼저 전송 대기 기록으로 저장하고 서버 전송은 백그라운드에서 처리합니다.
- 서버 전송에 실패하거나 전송 중 브라우저를 종료해도 대기 기록이 남습니다. Chrome 시작·확장 갱신·연결 복원·1분 간격 재시도에서 원래 계정으로 자동 재전송합니다. 서버가 해당 풀이의 저장을 확인한 뒤 임시 기록을 삭제합니다.
- 팝업에 임시 저장 건수와 자동 재전송 안내를 표시합니다. 전송 대기는 최근 동기화 완료 목록과 구분합니다. 같은 풀이 식별자로 재전송해 서버 저장과 GitHub 작업을 중복 등록하지 않습니다.
- 로그아웃·자동 동기화 OFF·다른 계정 로그인 중에는 대기 기록을 보존하고 전송을 중지합니다. 동일한 계정의 로그인과 동기화 권한이 복원되면 재개합니다. 기존 로컬 보관함과 과거 제출은 자동 전송 대상으로 바꾸지 않습니다.
- 사이트의 제출 동작을 방해하지 않으며, 서버 등록에 실패한 정답 풀이는 동기화 완료로 표시하지 않습니다.
- GitHub 일괄 커밋에서 중복 문제를 모든 제출·가장 최근·가장 빠른·최소 메모리 기준으로 선택할 수 있습니다. 일괄 커밋 영역을 GitHub 관리의 맨 아래로 옮기고 다른 카드와 폭을 맞췄습니다.
- 확장 팝업에 일괄 커밋 접수·처리 진행률과 성공·실패·확인 필요 건수를 표시합니다. 팝업을 닫았다 다시 열어도 진행 중 작업을 확인할 수 있습니다. 완료 결과는 현재 팝업에서 계속 확인할 수 있고, 화면을 새로고침하거나 팝업을 다시 열면 완료 카드가 사라집니다.
- 관리 화면 상단의 일괄 커밋 진행 표시를 제거했습니다. 진행 상태와 작업 이어가기·추가 요청 중단은 확장 팝업에서만 확인하고 처리합니다.
- 자동 동기화가 꺼져 있거나 연결이 만료돼도 현재 계정의 수동 일괄 커밋을 팝업에서 확인하고 중단할 수 있습니다. 작업 이어가기는 서버 로그인 계정을 다시 확인합니다.
- 최근 풀이 조회가 일시적으로 실패해도 팝업의 저장된 GitHub 연결·ON/OFF 설정을 유지하고 서버 연결 확인 안내를 표시합니다. 대시보드는 초기 연결 확인 전부터 연결 끊김으로 표시하지 않으며, 로그인 상태 읽기의 일시적인 통신 실패는 한 번 재시도합니다. 세션 만료는 재로그인이 필요합니다.

## 업데이트 안내

서버에서 실제로 만료되거나 로그아웃된 세션은 GitHub 재로그인이 필요합니다. 쿠키나 인증 정보를 복사해 강제로 복원하지 않습니다. 이전 버전의 다운로드 권한 승인으로 확장이 비활성화된 경우 다시 활성화해 주세요. 확장 갱신 전에 열린 문제 탭에는 새로고침 안내가 표시될 수 있으며, 작성한 코드를 확인한 뒤 새로고침해 주세요.

사이트의 정답 결과를 확인하고 기기에 임시 저장하기 전에 문제 탭이나 브라우저를 종료한 제출은 복구할 수 없습니다. 확장 삭제·사이트 데이터 제거·저장 공간 오류도 임시 기록 보존 범위 밖입니다. GitHub 자동 커밋은 서버의 현재 자동 커밋 설정과 저장소 연결이 유효해야 처리됩니다.

게시된 1.0.2 다음 업데이트로 배포합니다. 자동 배포 예약과 릴리스 태그의 웹스토어 자동 제출은 사용하지 않습니다. 기본 수동 실행은 업로드 없는 검증이며, 1.0.3은 수정 검증 후 수동으로 심사 제출합니다. 심사 제출과 실제 스토어 공개·설치 업데이트 확인은 구분합니다.
