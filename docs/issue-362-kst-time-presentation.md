# 사용자 시간 표시 KST 통일 — #362

## 표시 계약

- 복사/다운로드/확장 자동 다운로드/GitHub 문제 주석의 `Solved At`은 `yyyy-MM-dd HH:mm:ss KST`.
- 대시보드 상세·제출 선택기, 확장 팝업·로컬 보관함의 풀이 시각은 `yyyy-MM-dd HH:mm KST`.
- 목록의 날짜와 커뮤니티 공개 날짜는 `Asia/Seoul`의 달력 날짜.
- `{time}` 다운로드 파일명·Git 경로·커밋 메시지는 KST `yyMMddHHmmss`.
- Git 경로 충돌 시 제출별 시간 접미사도 KST `yyyyMMdd-HHmmssSSS`.
- Updated/신규 릴리스 날짜는 커밋의 오프셋 포함 시각을 KST로 변환한 날짜. 명시적인 날짜 override는 날짜 자체로 유지.
- JavaScript 공통 표시 함수와 Java 서버 formatter는 시스템/브라우저 시간대에 의존하지 않고 `Asia/Seoul`을 명시한다.

## 보존 및 UTC 호환

- DB/API/로컬의 `solvedAt`, `observedAt`, `syncedAt`과 원본 제출 ID의 시각은 UTC ISO/원본 계약을 유지한다. 시각 재저장이나 마이그레이션은 없다.
- 과거 수집의 KST 원본 → Instant 변환, 계정/제출 대조, 정렬/만료/작업 경과 시간은 변경하지 않는다.
- GitHub 기존 결과를 현재 대상 HEAD에 고정해 정확히 대조한다. 현재 KST 결과 또는 동일 설정으로 생성한 이전 UTC 주석이 원본 코드까지 일치하면 기존 성공으로 인정한다.
- 시간 경로 변경/충돌 시 이전 UTC 기본 경로·제출별 접미사 경로를 최대 두 곳 추가 조회한다. 조회 실패는 새 쓰기 전에 중단하며, 다른 코드나 비정상 파일을 동일 풀이로 처리하지 않는다.
- UTC 기존 파일을 이름 변경/덮어쓰기하거나 기존 커밋을 재작성하지 않는다. 확인된 신규 쓰기만 KST. UNKNOWN의 선택/재요청 금지는 유지한다.
- 내부 백업 폴더의 UTC 식별 시각, OAuth/DB 설정, 날짜만 있는 과거 공개 릴리스 메타데이터는 사용자 풀이 시간 변환 대상이 아니다.

## 검증 근거

- 대시보드 테스트: UTC 호스트에서 22파일/170테스트 통과.
- API 전체 테스트: 167개, 실패 0, 오류 0, 환경 의존 PostgreSQL 5개 skip. provider 집중 31개 모두 통과.
- 확장 전체 테스트: 미국 Los Angeles 시간대에서 타입 검사와 271개 테스트 통과. 브라우저 및 호스트의 로컬 시간대에 의존하지 않는다.
- 날짜/월/연도 경계, 명시적인 +09:00 입력의 중복 보정 없음, 결측/비정상 시각, observedAt fallback 검증.
- 기존 UTC 주석/시간 경로/충돌 접미사 복합 호환, 다른 원본 코드 구분, 실패 조회 후 쓰기 없음, pinned HEAD/non-force 보존 검증.
- Chrome 로컬 테스트 서버의 실제 App에서 상세 `2026-01-01 00:00 KST`, 주석 `Solved At: 2026-01-01 00:00:00 KST`, 파일명 `260101000000.java` 확인. 합성 데이터이며 실제 사용자 설정/풀이/GitHub에 쓰지 않았다.
- 같은 로컬 서버에서 실제 확장 팝업 렌더러의 합성 풀이가 `2026-01-01 00:00 KST`로 표시되는 것을 확인했다. 설치된 확장의 내부 페이지 직접 실행 검증과 구분한다.
- 대시보드/확장 빌드 성공. 기존 대시보드 Shiki 청크 크기 경고는 유지.
- 0.2.3 확장은 기존 등록 폴더에 백업 후 21개 빌드 파일을 반영한다. Chrome 내부 확장 페이지는 도구 정책상 조작할 수 없어 최종 재로드/팝업 확인은 사용자 담당.

실제 배포/릴리스 ID와 최종 확장 테스트·검토 결과는 Issue/PR 댓글에 추가한다. 사용자 최종 확인 전 #362는 열어 둔다.
