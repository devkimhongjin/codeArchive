# CodeArchive 설치·업데이트

출시 전 Chrome 데스크톱용 초대형 베타입니다. 운영자가 확인한 패키지만 사용하세요. 모바일 Chrome·다른 브라우저·관리 조직에서 차단한 확장 프로그램 설치는 이번 안내의 지원 범위가 아닙니다. 보안 정책을 우회하지 마세요.

## 준비물

- 데스크톱 Chrome과 SWEA 계정. 서버 기능에는 GitHub 계정도 필요합니다.
- 운영자에게 받은 `codearchive-beta-버전-커밋.zip` 및 같은 이름의 `.zip.sha256` 확인값
- 운영자 확인 메시지: 소스 커밋, 설치 대상 버전, 배포 상태, 알려진 제한, 문의 창구
- 운영자가 비공개로 별도 전달한 Dashboard 초대 비밀번호 (저장소·ZIP 안에는 없음)

패키지는 후보일 수 있습니다. `release-info.json`의 `distributionStatus`가 `candidate`이면 운영자의 최종 사용 안내가 있기 전까지 검증용입니다. SHA-256 일치는 파일이 전달 중 바뀌지 않았는지 확인할 뿐, 안전성 인증이나 배포 승인을 뜻하지 않습니다.

Windows에서 선택적으로 확인하려면 다운로드한 ZIP에 대해 실행합니다.

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath 'C:\다운로드경로\받은파일.zip'
```

표시된 Hash가 운영자가 별도로 알려준 값과 같아야 합니다. 다르면 설치하지 말고 다시 문의하세요. 파일명은 실제 받은 이름으로 바꿉니다.

## 처음 설치하기

1. ZIP을 계속 보관할 전용 폴더에 압축 해제합니다. 예: Windows `문서\CodeArchiveBeta`, macOS 홈 폴더 아래 `CodeArchiveBeta`. ZIP 안에서 직접 열지 마세요.
2. 압축 해제한 폴더에 `extension/manifest.json`, `docs/`, `release-info.json`이 있는지 확인합니다.
3. Chrome 주소창에 `chrome://extensions`를 직접 입력합니다.
4. 오른쪽 위 **개발자 모드**를 켭니다.
5. **압축해제된 확장 프로그램을 로드합니다**를 누르고 **`extension` 폴더**를 선택합니다. ZIP이나 한 단계 위 폴더가 아닙니다.
6. CodeArchive 카드가 켜져 있고 오류가 없는지 확인합니다. ID는 반드시 `oohlcmihldmfninmdcmanddfmhoonmdl`이어야 합니다. 다르면 자동 동기화를 켜지 말고 문의하세요.
7. Chrome 오른쪽 위 확장 프로그램 메뉴에서 CodeArchive를 고정하면 편리합니다.
8. 설치 전에 열어 둔 SWEA 풀이 탭을 새로고침합니다. 새로고침 전 작성 중인 코드는 별도 파일에 보관하세요.
9. CodeArchive 팝업의 **로컬 풀이 보기**와 **전체 풀이 보기**가 열리는지 확인합니다. 다음은 [사용 가이드](dashboard-beta-tester-guide.md)입니다.

설치 폴더는 계속 같은 위치에 두세요. 개발자 모드 경고가 나타날 수 있지만 보호 기능을 끄거나 출처 불명 패키지를 허용하는 절차는 필요하지 않습니다.

Chrome의 기본 설치·갱신 방식은 [공식 압축 해제 확장 프로그램 안내](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked)를 따릅니다.

## 기존 사용자 업데이트 — 먼저 보존

**기존 Extension을 제거하지 않습니다.** 같은 Chrome 프로필·같은 ID·기존 로드 폴더를 유지해 갱신합니다. 무조건 보존된다고 보장할 수 없으므로 중요한 코드는 먼저 내보냅니다.

1. Dashboard의 **자동 동기화**를 끄고 SWEA의 작성 중인 코드도 따로 저장합니다.
2. **로컬 풀이 보기**에서 필요한 풀이를 각각 선택해 **Source**와 **Markdown**으로 내려받습니다. 전체 기록 일괄 백업 버튼은 아직 없습니다. 내려받은 파일이 정상적으로 열리는지도 확인하세요.
3. 기존 로컬 건수와 Extension ID를 기록합니다. 코드나 개인정보를 공개 채널에 첨부하지 않습니다.
4. 새 ZIP은 기존 폴더와 다른 임시 위치에 먼저 압축 해제하고 해시·버전을 확인합니다.
5. 새 패키지의 `extension` **내부 파일과 하위 폴더**를 기존 Chrome에 로드한 폴더에 복사·덮어씁니다. 이 작업은 프로그램 파일 갱신이며 Chrome 프로필/IndexedDB 삭제가 아닙니다. 오래된 파일 정리가 필요하면 운영자 안내를 받으세요.
6. `chrome://extensions`의 기존 CodeArchive 카드에서 **새로고침** 아이콘을 누릅니다. 제거 후 새로 설치하지 않습니다.
7. SWEA와 Dashboard 탭을 새로고침하고 ID·로컬 기록을 먼저 확인합니다.
8. 로컬 기록이 정상이고 로그인 계정이 맞을 때만 자동 동기화를 다시 켭니다.

업데이트 실패 시 자동 동기화를 끈 채 중단하고 [문제 해결 안내](beta-troubleshooting.md)에 따라 문의합니다. 브라우저 저장소 지우기·프로필 삭제·임의의 이전 버전 덮어쓰기는 하지 마세요. 저장소 스키마가 바뀌면 구버전이 기록을 읽지 못할 수 있습니다.

## PC 이동·복원·사용 중단

- 로컬 기록은 해당 Chrome 프로필의 Extension 저장소에 있습니다. 설치 폴더 복사만으로 다른 PC에 기록이 이동하지 않습니다.
- Source/Markdown은 사람이 확인할 수 있는 사본입니다. 내부 ID·동기화 확인 상태까지 완전히 복원하는 백업은 아닙니다.
- 팝업 **파일 가져오기**는 단일 소스 파일 또는 호환 풀이 JSON을 읽어 새 풀이를 만드는 기능입니다. 중복 방지 정보까지 복원하는 전체 복원 기능으로 사용하지 마세요.
- 사용을 멈추려면 먼저 자동 동기화를 끄고 Dashboard에서 로그아웃합니다. 중요한 기록을 내보내기 전 Extension 제거/프로필 초기화를 하지 않습니다.
- Extension 제거는 서버 풀이 삭제나 계정 삭제와 동일하지 않습니다. 서버 데이터 관련 요청은 운영자에게 문의하세요.
