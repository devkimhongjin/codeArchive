# 간단한 Dashboard 입장 비밀번호

2026-08-31 사용자 결정: 개인 프로젝트이므로 **Dashboard에 들어갈 때 한 번만 비밀번호를 확인**한다. 계정별 초대·서버 전체 접근 제한·입장용 쿠키/토큰·주기적 재인증은 추가하지 않는다.

## 동작

1. 새 Dashboard 탭에서 초대 비밀번호 입력 화면을 보여준다. 아직 App을 마운트하지 않으므로 정상 UI에서는 로그인 확인·Extension 연결·자동 동기화를 시작하지 않는다.
2. `POST /api/v1/beta/access`에 HTTPS JSON `{password}`를 전송한다. 인증 쿠키를 보내지 않고, 기존 exact Dashboard Origin만 허용한다.
3. 서버가 비밀 설정 `CODEARCHIVE_BETA_ACCESS_PASSWORD`와 비교한다. 8~128자 설정이 없으면 503으로 닫고, 틀리면 403을 반환한다. 성공은 공통 ApiResponse의 `{accepted: true}`이며 no-store이다. 비밀번호/해시를 응답하거나 로그에 남기지 않는다.
4. 성공하면 **승인 여부만** `sessionStorage`에 보관한다. 같은 탭의 새로고침·GitHub 로그인 후 복귀에서는 다시 묻지 않는다. 입력 문자열은 요청 후 지우며 저장소·URL에 남기지 않는다.
5. 보통 탭을 닫고 새로 열면 다시 입력한다. 브라우저의 탭 복제/세션 복원은 sessionStorage를 복사·복원할 수 있다. 저장소를 사용할 수 없는 환경은 현재 화면에서만 승인하고 새로고침 시 다시 입력한다.

기존 GitHub 로그인, 계정별 풀이 권한, 자동 동기화 동의, AI 요청별 동의와 한도는 그대로 유지한다. Extension 로컬 기능에는 비밀번호가 필요 없다.

## 의도된 한계

이것은 **편의용 화면 제한이지 서버 자원에 대한 접근 제어가 아니다.** sessionStorage 값을 바꾸거나 자체 클라이언트/API를 사용하면 우회할 수 있다. 기존 OAuth/API 경로를 막거나 로그인 세션을 폐기하지 않는다. 비밀번호를 바꿔도 이미 통과한 탭은 다시 묻지 않는다. 공유 비밀번호 재전달, 정적 파일 다운로드, 직접 요청량을 막지 못하며 이번 범위에는 brute-force/edge 차단도 없다.

나중에 실제 비용/악용을 제한해야 하면 서버 접근 게이트나 GitHub 계정 allowlist를 별도 구현한다. 이 한계를 숨기고 초대받은 사람만 서버를 쓸 수 있다고 안내하지 않는다.

## 운영

Main API에 `CODEARCHIVE_BETA_ACCESS_PASSWORD`만 비밀 설정으로 추가한다. `VITE_` 변수·Git·README·ZIP·이슈·초대 양식에는 실제 값을 넣지 않는다. 테스터에게는 비공개 연락으로 따로 알려준다. 배포·비밀 설정 변경은 각각 실행 직전 승인 대상이며 이번 코드 작업은 현재 서비스를 바꾸지 않는다.

DB·Extension 권한·기존 인증 필터·배포 자원 변경 없음. Main API와 Web 모두 승인된 develop SHA로 반영해야 입장 화면이 동작한다. 구 API/설정 누락/네트워크 오류에서는 입장 오류를 보여주며 UI를 자동으로 열어주지 않는다.
